# ADR-002 确定性、固定步长与 RNG 分流入档

> **决策（2026-08-12，主理人游承峰转呈用户拍板）：采纳选项 2 —— 纯 float + 禁用 fast-math + 量化写回 + `Fix` 兜底。**
> 理由：非全局定点、非容差比对，在 PC x64 单平台（同 Unity 版本 + 同 Burst 设置）以零额外成本达成逐位一致，并保留 `Fix` 作跨平台 / 回退 2 兜底。

## 背景（Context）
R13（连续时间确定性/可重放）已裁决为 **P0，并升级为 Phase 3 Gate-0 首道里程碑门**（S4 §7.3）。Replay 四路对跑要求：同 seed + 同干预序列，在 1× / 20× / 变速 / 存读档下，**关键指标哈希逐月完全一致（≥120 游戏月）**。五条铁律已定（固定步长唯一时间源 / 双频按边界时间戳升序合并 / 稳定 ID 排序遍历 / RNG 分流入档 / 禁不确定并发与浮点漂移）。本 ADR 落实"浮点 vs 定点"与"RNG 分流入档"两项工程决策。

## 决策（Decision）
1. **固定步长是唯一时间源**：所有逻辑只读 `gameClock` 与 pass 序号；禁止墙钟/帧计数/系统时间（铁律 1）。
2. **RNG 分流入档**：每子系统持 `worldSeed` 派生的独立确定性 PRNG 流（xoshiro256**），**禁用 `System.Random`**；所有流状态随 `WorldState` 序列化（铁律 4）。
3. **浮点优先 + 定点兜底（推荐）**：
   - MVP / Gate-0（PC x64 单平台）：受控 IEEE-754 float + **禁用 fast-math** + `UnityEngine.Mathematics` 确定性运算即可逐位一致。
   - **量化写回边界**：所有进入指标哈希、所有跨月持久化的累加量在写回前 `Quantize(x, decimals)`（等价定点截断），消除尾差累积。
   - 保留 `Fix`（Q 格式，如 32.32）类型于 `Simulation.Core.Math`，供**回退 2 / 跨平台**使用；对争议累加量（人口增长率、资源再生、Logistic 种群）直接以 `Fix` 运算。
4. **三级回退**（沿用 S4 §7.3）：降速度档 → 串行化定点化 → lockstep。

## 被否决备选（Rejected Alternatives）

> 选项 2 已采纳（见上方决策与 §决策）。以下为被否决的备选方案及不采用理由。

### 选项 1 — 全局定点数（Q 格式）从头到尾
- 优点：跨平台逐位确定，无需担忧 float 漂移。
- 缺点：① 实现成本高（整套模拟数学重写，三角函数/Logistic/sqrt 需定点库）；② 性能下降（定点运算慢于硬件 float，尤其 Burst）；③ 与 Unity 现有 float 生态（Mathematics、动画、渲染插值）割裂，需在边界频繁转换。
- 结论：过重，**仅作为回退 2 的局部手段**，不全局采用。

### 选项 3 — 容忍 float 漂移，仅比对"容差内一致"
- 优点：零额外工作。
- 缺点：**违反 Gate-0 规范**（要求逐月哈希完全一致，非容差）；且漂移会随月累积放大，长程（≥120 月）必分叉；破坏存档可重放承诺。
- 结论：否决。

## 后果（Consequences）
- 正向：Gate-0 在 PC 单平台以最小成本达成逐位一致；量化写回 + `Fix` 兜底覆盖跨平台与回退 2；RNG 分流入档使存读档/变速不依赖运行序。
- 负向：须在 CI 锁定"同 Unity 版本 + 同 Burst 设置"，且 `Quantize` 边界需审慎选择（过粗丢失精度、过细仍可能漂移）；跨平台 Replay 需触发 `Fix` 全局切换。
- 约束：所有 RNG 抽取仅在 pass 内、稳定 ID 序下发生；表现层随机使用独立非确定流，不得进逻辑。

## 采纳记录（已拍板）
- [x] 已采纳 **选项 2（纯 float + 禁 fast-math + 量化写回）+ `Fix` 兜底**（2026-08-12，主理人游承峰转呈用户拍板），非全局定点。
- 历史风险说明（已不触发）：若产品未来要求"跨平台（Mac/ARM）逐位 Replay"，将自动启用 `Fix` 全局切换（回退 2 路径），带来性能与实现成本；当前平台（桌面 PC Windows）Gate-0 不受影响。
