# ADR-004 世界状态序列化 / LOD 数据组织

> **决策（2026-08-12，主理人游承峰转呈用户拍板）：采纳选项 1 —— 全量二进制快照 + 命令日志 + LOD 分块 + delta。**
> 理由：读档后逐位一致、Replay 路径④ 直接成立、兼容全球 LOD 分层与增量 delta，支持回放与确定性校验。

## 背景（Context）
世界状态体量大（全球 `WorldTile` 网格 + 所有聚落/政体/个体 + 生态种群 + 编年史），且须支持 **存读档 Replay（Gate-0 路径④）**：读档后演化须与无存档路逐月哈希一致。同时全球尺度下须按 LOD 分层以降低 IO 与内存（S5 §2.3）。本 ADR 确定序列化分层与 LOD 数据组织。

## 决策（Decision）
- **分层序列化**：确定性态层（全量 `WorldState`）+ 个体层（随确定性态一并序列化）+ 历史层（编年史，增量追加）。
- **全量快照 + 命令日志**：月边界序列化 `WorldState`（含 `RngRegistry` 全状态、`InterventionLog`、时钟/累加器、模块开关）；读档恢复逐位一致态 → 续跑等价于无存档路（Gate-0 路径④成立）。
- **格式**：二进制主存（显式小端、自定义 writer，禁 `BinaryFormatter`）+ JSON 配置（`WorldInitConfig` / `region-presets.json` / 模块开关）；高频量先 `Quantize`（呼应 ADR-002）。
- **WorldTile LOD 分块**：High 区逐 tile 全量，Mid/Low 聚合压缩；读档先载 High + 焦点 Mid，远域 Low 异步延迟装载（不阻塞逻辑）。
- **增量 delta**：历史层与高频生态指标用 delta 追加，降低 IO。

## 被否决备选（Rejected Alternatives）

> 选项 1 已采纳（见上方决策与 §决策）。以下为被否决的备选方案及不采用理由。

### 选项 2 — 纯命令日志（ event-sourcing，仅存 seed + 干预序列）
- 优点：存档极小。
- 缺点：读档需从 seed **重算全程**至当前月 → 慢（≥120 月重算）；且任何 pass 实现变更都破坏旧档兼容；不适合"随时读档续玩"。
- 结论：不纯用；命令日志仅作 Replay 测试输入与辅助。

### 选项 3 — JSON 全量
- 优点：人读。
- 缺点：体量大、序列化慢、浮点文本化引入精度/确定性风险。
- 结论：仅用于配置/元数据，确定性态不用。

## 后果（Consequences）
- 正向：存读档 Replay 等价性有结构保证；LOD 分块控制内存/IO；二进制 + Quantize 保确定性。
- 负向：需自写确定性二进制 writer（一次性）；全球网格快照仍须 LOD 压缩避免膨胀；旧版本存档兼容需版本号 + 迁移策略（预留 `schemaVersion`）。
- 约束：序列化不得依赖任何非确定序（字典遍历需排序后写）；`WorldState` 为唯一真相源，禁止逻辑态散落他处。

## 采纳记录（已拍板）
- [x] 已采纳 **选项 1（全量二进制快照 + 命令日志 + LOD 分块 + delta）**（2026-08-12，主理人游承峰转呈用户拍板）。
- 历史风险说明（已不触发）：若选纯命令日志（选项 2），读档体验与"随时续玩"受损，且 pass 实现演进会废旧档；不采用。
