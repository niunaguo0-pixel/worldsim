干预系统 GDD

1. 系统概述

一句话定义：干预系统是玩家与世界交互的唯一接口——玩家不操控任何个体或单位，而是以"神谕/天命"的形式间接调节世界参数，影响生态、文明与生存三个维度。干预次数不限，平衡来自干预的自然生态后果而非人为配额。

设计目标： - 让玩家感到"是我在影响世界"而非"在看自动模拟器"（R1） - 在"干预太强→变成建造游戏"与"干预太弱→变成观看模拟"之间找到平衡点（R2） - 为三支柱提供咬合的焊接点——每次干预同时触及三根支柱

与概念文档的对齐： - 概念文档 3.1.1 定义了 5 种干预类型与"干预无限制"机制（v1.2.0 移除了干预力点数） - 概念文档 3.4 核心循环中，"③ 施加干预"是三支柱咬合的焊接点 - 概念文档 R1/R2 是本系统首攻的两个 P0 级风险 - 概念文档 3.1.4 时间系统为月历制（1 月 = 1 回合，12 月 = 1 年，3 月 = 1 季）

2. 机制设计（Mechanics）

2.1 干预无限制与自然后果制衡（Unlimited Intervention & Natural Consequence Balancing）

干预系统的核心设计变更（v1.1.0）：玩家可随时、任意次地施加干预，没有点数、配额或次数限制。 平衡不来自人为的资源稀缺，而来自干预在生态系统中引发的自然连锁反应。

设计原则：

原则 说明
无限干预 玩家每月可施加任意次数的干预，无点数消耗、无配额上限
自然后果 每次干预都在生态系统中引发连锁反应——频繁降雨导致洪涝，过度投放资源导致生态失衡，过度引导文明导致生态退化
延迟显现 干预的末端后果可能跨越 3-12 个月才显现，玩家无法即时掌控全部 outcomes
反噬机制 过度干预（同区域同类型干预叠加超阈值）触发反噬——系统以更剧烈的负面连锁反应"推回"玩家
经验学习 玩家通过试错学会"有所为有所不为"——不是系统告诉你"不能做"，而是世界告诉你"做多了会出事"

反噬阈值示例：

干预类型 安全区间 反噬触发 反噬表现
气候调节（降雨） 同区域 3 个月内 ≤ 2 次 3 个月内 ≥ 3 次 洪涝 → 水土流失 → 疫病概率上升
资源投放 同区域 6 个月内 ≤ 3 次 6 个月内 ≥ 4 次 资源过剩 → 种群爆发 → 食物链失衡
文明引导 同聚落 6 个月内 ≤ 2 种倾向 6 个月内 ≥ 3 种倾向 文明决策混乱 → 内部冲突 → 稳定度下降
灾厄施加 同区域 12 个月内 ≤ 1 次 12 个月内 ≥ 2 次 生态不可逆损伤 → 世界健康度下降

设计意图： - 无限权力 + 复杂后果：玩家拥有无限的干预权力，但面对的是一个比玩家更复杂的系统。权力不受限，但后果不可完全预测——这是"敬畏式权力感"的机制基础。 - 试错式学习：玩家不会被系统告知"你不能做这个"，而是通过世界的反馈学到"做这个会有后果"。这比硬性配额更有沉浸感。 - ** emergent 平衡**：平衡点不是设计师设定的数值，而是从生态模拟的复杂性中涌现的——不同世界状态下的反噬阈值不同，玩家需要持续适应。

2.2 干预类型（Intervention Types）

2.2.1 气候调节（Climate Adjustment）

属性 值
作用域 地理区域级（一个气候格子，约 1/8 地图）
效果 修改区域降雨量 ±30%、温度偏移 ±5°C，持续 2-3 个月
三支柱触及 生态：改变水文/植被 → 建设：影响农业产出 → 生存：缓解/加剧灾害

机制细节： - 玩家选择一个区域 + 调节方向（增雨/减雨/升温/降温） - 效果不是瞬间的——降雨量在 1 个月内渐变到位，持续 2-3 个月后自然回落 - 副作用：上游增雨 → 下游水量增加 → 可能引发洪涝（远期后果） - 反噬：同区域 3 个月内累计 ≥ 3 次降雨调节 → 触发洪涝反噬 - MVP 简化：仅增雨/减雨两种，作用域固定为 1 个区域

2.2.2 资源投放（Resource Placement）

属性 值
作用域 局部点级（地图上一个格子）
效果 在指定位置生成资源节点（水源/矿脉/可种植土地/鱼群）
三支柱触及 建设：提供建材/食物 → 生态：改变开采压力 → 生存：缓解资源短缺

机制细节： - 玩家选择一个空地格子 + 资源类型 - 资源节点有初始储量，被文明采集后递减，可再生资源可缓慢恢复 - 副作用：投放水源可能改变局部生态（湿地扩张），投放矿脉可能引发过度开采 - 反噬：同区域 6 个月内累计 ≥ 4 次资源投放 → 触发生态失衡反噬（种群爆发/资源浪费） - MVP 简化：仅水源和可种植土地两种

2.2.3 物种迁移（Species Migration）

属性 值
作用域 区域间级（从 A 区域引导至 B 区域）
效果 引导一个物种群从 A 区域迁移至 B 区域
三支柱触及 生态：改变两地种群分布 → 建设：可能带来新资源或新威胁 → 生存：可能引入兽患或提供猎物

机制细节： - 玩家选择一个物种群 + 目标区域 - 迁移不是瞬间的——物种群在 1-2 个月内逐步移动到目标区域 - 副作用：引入的物种可能成为入侵物种，破坏目标区域生态平衡 - 反噬：同区域 6 个月内引入 ≥ 3 个不同物种群 → 触发入侵物种反噬 - MVP 简化：MVP 不包含此干预（核心层引入）

2.2.4 灾厄/恩赐（Disaster/Blessing）

属性 值
作用域 区域/文明级
效果 施加灾害（旱灾/兽患/疫病）或恩赐（丰收/发现/灵感）
三支柱触及 生存：直接施加/缓解威胁 → 生态：触发种群波动 → 建设：迫使文明适应或崩溃

机制细节： - 灾厄可用于"修剪"过度膨胀的文明或生态（如对过度砍伐的聚落降旱灾） - 恩赐种类：丰收（农作物产量 ×1.5 持续 1 季）、发现（随机解锁一项科技）、灵感（聚落幸福度提升） - 反噬：同区域 12 个月内施加 ≥ 2 次灾厄 → 触发生态不可逆损伤反噬 - MVP 简化：仅旱灾和丰收两种

2.2.5 文明引导（Civilization Guidance）

属性 值
作用域 聚落级
效果 向聚落注入发展倾向（农业/狩猎/防御/商业/信仰/军事/族群/文化），写入 S3 的 devBias_* 权重，影响其 AI 决策
三支柱触及 建设：注入发展方向 → 生态：改变土地利用方式 → 生存：改变抗灾策略

机制细节： - 玩家选择一个聚落 + 发展倾向 - 倾向不是命令——聚落 AI 的决策权重被调整（如"农业倾向"使 AI 在选择行动时优先开垦农田），但 AI 仍会根据环境自主决策 - 倾向持续 3-5 个月后衰减（不是永久效果） - 副作用：强引导农业可能导致过度开垦→森林砍伐→生态退化 - 反噬：同聚落 6 个月内注入 ≥ 3 种不同倾向 → 触发文明决策混乱反噬 - 军事/战争方针（核心层开放）：写入 devBias_military，偏移文明军备方向（尚武/扩张 vs 守势/城防），详见 S3 §2.10.4；玩家绝不指挥具体部队 - 族群方针（核心层开放，v1.1.3 新增）：写入 devBias_ethnicity，偏移文明的迁移开放度/同化倾向（间接影响 mixingRate 与边界开放度），详见 S3 §2.11；玩家绝不指定某国民族构成或某族群属性 - 文化方针（核心层开放，v1.1.3 新增）：写入 devBias_culture，偏移文明的文化开放/守传统倾向（间接影响文化特质生成方向、CultureProfile 演化），详见 S3 §2.8；玩家绝不指定具体文化内容 - MVP 简化：仅农业倾向和狩猎倾向两种；商业/信仰/防御/军事/族群/文化在核心层开放；"扩张"由多聚落模块承载，非基础 devBias

2.3 紧急干预（Emergency Intervention）

当文明面临不可逆崩溃时（R3 关联），玩家可使用紧急干预力挽狂澜。紧急干预无点数消耗，但有冷却时间（以月计），防止滥用。

紧急干预 效果 冷却
天降甘霖 立即终止一场旱灾，恢复区域降雨至正常水平 24 个月（2 年）
神佑护盾 保护一个聚落免受下一次灾害影响 24 个月（2 年）
生命之泉 立即恢复一个聚落 50% 粮储 24 个月（2 年）

设计意图：紧急干预是 R3 的"安全阀"——当世界走向不可逆崩溃时，给玩家最后一次机会。冷却时间（2 年 = 24 个月）确保它不会被滥用——在冷却期间，玩家必须依靠常规干预和策略来维持文明。冷却不是点数限制，而是"神力需要恢复"的叙事化时间约束。

2.4 数据模型

// 干预行动
struct InterventionAction {
    InterventionType type;    // 干预类型（枚举）
    Vector2 targetLocation;   // 目标位置（世界坐标）
    float radius;             // 作用半径
    Dictionary parameters;    // 干预参数（如降雨量偏移、资源类型等）
    int delayMonths;          // 效果延迟月数（0=即时）
    int durationMonths;       // 效果持续月数
    int monthExecuted;        // 执行时的月数（世界时间戳）
}

// 干预效果实例（运行时追踪）
struct InterventionEffect {
    int actionId;             // 关联的干预行动ID
    InterventionType type;    // 干预类型
    Vector2 epicenter;        // 效果中心
    float currentIntensity;   // 当前强度（随时间衰减）
    int remainingMonths;      // 剩余持续月数
    List<AffectedEntity> affectedEntities; // 受影响的实体列表
}

// 反噬追踪器（用于检测过度干预）
struct BacklashTracker {
    InterventionType type;           // 干预类型
    Vector2 regionCenter;            // 区域中心
    List<int> recentInterventionIds; // 近期同区域同类型干预记录
    int windowMonths;                // 检测窗口（月数）
    int threshold;                   // 反噬触发阈值
    bool backlashTriggered;          // 是否已触发反噬
}

// 因果链节点（用于追踪远期后果）
struct CausalChainNode {
    int interventionId;       // 干预行动ID
    int monthExecuted;        // 执行月数（世界时间戳）
    List<WorldEvent> triggeredEvents; // 触发的世界事件
    List<CausalChainNode> downstreamNodes; // 下游因果节点
}

// 紧急干预冷却状态
struct EmergencyCooldown {
    EmergencyType type;       // 紧急干预类型
    int remainingCooldownMonths; // 剩余冷却月数
    bool isAvailable;         // 是否可用
}

3. 动态行为（Dynamics）

3.1 预期涌现行为

D1 — 干预涟漪（Intervention Ripple）

玩家向上游降雨 → 下游水量增加 → 鱼群繁殖 → 渔获上升 → 聚落食物盈余 → 人口增长 → 伐木扩建 → 森林缩减 → 水土流失 → 河流含沙量上升 → 下游渔场退化。一条干预的因果链可能跨越 3-12 个月才显现末端后果。

GDD 设计对策：因果链追踪系统（见 2.4 数据模型）记录每次干预的下游影响链。当末端后果显现时，UI 以"追溯"形式提示玩家"此事件与 N 个月前的某次干预有关"——这是 R1（agency 感）的关键设计。

D2 — 自然后果博弈（Natural Consequence Budgeting）

玩家可以无限干预，但每次干预都在累积生态压力。玩家需要在"立即解决问题"与"避免触发反噬"之间权衡——"这个月已经降雨两次了，再降一次可能引发洪涝，但旱灾还在加剧……"。

GDD 设计对策：这是 R2 的核心体验——平衡不来自资源稀缺，而来自后果预判。反噬追踪器（见 2.4）在玩家接近反噬阈值时以 UI 预警提示（"该区域近期降雨频繁，继续增雨可能引发洪涝"），让玩家做知情决策而非盲试。关键平衡点在于：反噬阈值不能太低（否则玩家感到被限制），也不能太高（否则干预无后果）。

D3 — 过度干预反噬（Over-Intervention Backlash）

玩家频繁降雨 → 区域长期过湿 → 植被疯长 → 食草动物爆发 → 食肉动物跟随爆发 → 种群失衡 → 疫病概率上升。看似"好意"的干预可能引发连锁反噬。

GDD 设计对策：干预不是"无脑施放就有好结果"——每次干预都有潜在的副作用链。反噬机制确保"无限干预"不等于"无限控制"——你可以做任何事，但世界会推回来。这服务于 R2（干预与涌现性的矛盾）。

D4 — 策略多样性涌现（Strategy Diversity Emergence）

因为干预无次数限制，不同玩家会发展出截然不同的干预风格——有的玩家是"微调型"（每月少量精准干预，避免反噬），有的玩家是"大手笔型"（攒一波大规模干预然后承受反噬后果），有的玩家是"观察型"（极少干预，让世界自运转）。没有"正确"的干预频率。

GDD 设计对策：这是移除点数限制后的意外收益——点数系统会强制所有玩家进入相同的"稀缺博弈"模式，而无限干预 + 自然后果允许玩家自定义自己的干预节奏。需在 playtest 中验证不同风格是否都能产生有意义的体验。

3.2 边界情况

边界情况 处理方式
同一区域叠加多次同类干预 效果叠加但有衰减系数（第二次 70%，第三次 50%），达到反噬阈值后触发反噬
干预目标区域不存在（如对干涸河床降雨） 允许执行，效果为"预置水源"——下次有水时生效
紧急干预冷却中再次尝试 UI 灰化，显示剩余冷却月数
玩家长时间不干预（只观察） 允许——世界自运转，但可能因无人干预而走向崩溃（R3）
玩家在同一月内对同一目标施加大量同类干预 允许执行，但反噬检测器立即预警并可能当月触发反噬
反噬触发后玩家继续同类干预 反噬效果加剧，可能导致生态不可逆相变（D3 机制）

4. 系统交互（System Interactions）

4.1 接口契约

干预系统向其他系统提供统一的干预接口，其他系统通过注册"可被干预的参数"来响应：

// 干预系统向其他系统暴露的接口
interface IInterventionTarget {
    // 注册可被干预的参数
    void RegisterInterventionParameter(string paramKey, float defaultValue, float min, float max);

    // 干预系统调用：修改参数
    void ApplyIntervention(string paramKey, float deltaValue, int durationMonths);

    // 干预系统调用：查询当前状态（用于 UI 显示）
    float GetParameterValue(string paramKey);
}

// 各系统实现此接口：
// S2 生态模拟引擎：注册降雨量、温度、物种出生率等参数
// S3 文明发展系统：注册发展倾向权重、粮储系数、科技解锁等参数
// S4 时间推进系统：注册时间流速参数（可选，远景层）

4.2 交互关系

交互系统 方向 内容
S2 生态模拟引擎 S1 → S2 气候调节修改降雨/温度参数；物种迁移修改种群位置；灾厄/恩赐影响种群动态；反噬效果通过 S2 的生态连锁实现
S3 文明发展系统 S1 → S3 资源投放在聚落附近生成资源节点；文明引导修改 AI 决策权重；恩赐提升粮储/科技
S4 时间推进系统 S4 → S1 每月开始时推进干预效果持续时间；月终结算时推进反噬检测器窗口；推进紧急干预冷却
S6 涌现叙事引擎 S1 → S6 干预行动作为事件源传入叙事引擎；因果链节点作为叙事素材；反噬事件作为重大叙事节点
S8 UI/HUD 系统 S1 ↔ S8 UI 显示干预光标、反噬预警、紧急干预冷却状态；玩家通过 UI 选择干预类型和目标
S9 相机系统 S1 → S9 干预光标位置影响相机聚焦（可选）

5. 范围分层（Scope Layering）

5.1 MVP 范围

维度 MVP 实现
干预类型 3 种：气候调节（增雨/减雨）、资源投放（水源/可种植土地）、文明引导（农业/狩猎倾向）
干预限制 无限制——无次数、无点数、无配额
反噬机制 基础版：仅气候调节有反噬（3 次降雨 → 洪涝），其他类型反噬在核心层实现
紧急干预 1 种：天降甘霖（终止旱灾，24 个月冷却）
视觉反馈 金色光环 + 涟漪扩散（即时）；目标区域参数变化（1 个月内渐变）
因果链追踪 基础版：记录干预→直接后果（1 层），不追踪远期链
UI 干预类型选择面板、干预光标、反噬预警提示（接近阈值时）、紧急干预冷却显示

5.2 核心层范围

维度 核心层实现
干预类型 5 种全部：气候调节、资源投放、物种迁移、灾厄/恩赐、文明引导
干预限制 无限制——反噬机制完整覆盖所有干预类型
反噬机制 完整版：所有干预类型均有反噬阈值与反噬效果；反噬强度随叠加次数递增
紧急干预 3 种全部：天降甘霖、神佑护盾、生命之泉（各有 24 个月冷却）

5.3 延展层方向

  • 群体性干预（一次干预影响多个区域）
  • 条件触发干预（设置自动触发条件，如"粮储低于 20% 时自动投放食物"）
  • 干预组合效果（特定干预组合产生特殊效果）
  • 反噬的正面化（某些"反噬"在特定条件下可能产生正面效果——如洪涝后土壤更肥沃）

6. 风险与未决问题

6.1 本系统特有风险

# 风险 级别 说明 待解方向
IV1 反噬阈值平衡 P0 反噬阈值太高 → 干预无后果，变成建造游戏；太低 → 玩家感到被隐形限制。3 次/3 月的起点是否合适？ MVP 原型阶段以气候调节反噬（3 次/3 月 → 洪涝）为起点，通过 playtest 观察玩家是否感到"干预有后果但不 frustrating"，迭代调整阈值与窗口。
IV2 因果链可追踪性 P0 远期后果（3-12 个月后才显现）玩家能否将其归因到自己之前的干预？如果玩家无法建立因果认知，agency 感就断了。 1) 因果追溯提示（远期后果显现时 UI 提示"此事件与 N 个月前的干预有关"）；2) 干预历史记录面板（玩家可翻阅自己的干预记录）；3) 效果可视化（干预落点保留淡金色微光持续 1 个月，作为"印记"）。MVP 验证基础版（1 层因果），核心层验证完整版（多级因果链）。
IV3 文明引导的间接感 P1 "发展倾向"调整 AI 权重——玩家能否感知到"是我引导的"而非"它自己发展的"？ 1) 引导生效时聚落头顶显示引导图标（持续 3-5 个月）；2) 引导导致的决策变化以事件通知形式提示（"聚落 X 在你的引导下开始发展农业"）；3) 引导效果可见且可量化（农田面积增长速度提升）。
IV4 干预副作用的可接受性 P1 玩家做了"好意"干预却引发反噬（如降雨导致洪涝），玩家可能感到不公平——"我只是在帮忙，为什么惩罚我？" 1) 反噬不是立即惩罚——有 2-3 个月的预警窗口（如"河流水位持续上升"）；2) 反噬的严重度与干预过度程度成正比——适度降雨无反噬，过度降雨才触发；3) UI 在干预预览时提示潜在风险（"该区域近期已多次降雨，继续增雨可能引发洪涝"）。
IV5 无限干预的认知负荷 P1 移除点数限制后，玩家可能陷入"什么都想干预"的焦虑——没有系统告诉你"够了"，玩家需要自己判断何时停手。 1) 反噬预警 UI 作为"软性引导"——不强制限制，但提示玩家"这里可能做过头了"；2) 事件通知的智能筛选——只推送重要事件，不让玩家感到需要干预所有事；3) playtest 观察玩家是否自然发展出"干预节奏感"。

6.2 与 P0/P1 风险的关联

概念文档风险 本 GDD 的攻关措施
R1 间接控制 agency 感 即时视觉反馈（金色光环+涟漪）→ 干预有回应感；因果链追踪 → 远期后果可归因；干预历史记录 → 玩家有"行动档案"；反噬机制 → 干预有可见的世界影响——agency 感来自可见的因果影响力而非资源稀缺
R2 干预与涌现性矛盾 自然后果制衡确保干预不能完全控制世界——每次干预都有潜在副作用；反噬机制确保过度干预有代价；延迟后果确保干预效果不即时可控；紧急干预有冷却限制
R3 涌现不可控性 紧急干预作为安全阀（24 个月冷却，无点数消耗）；灾害预警窗口给玩家反应时间；反噬预警给玩家"收手"信号

7. 验证标准（Validation Criteria）

7.1 MVP 验证假设

# 假设 验证方法 通过标准 不通过时的调整方向
V1 间接控制能让玩家感到 agency Playtest 观察：玩家是否在干预后密切关注世界变化？是否主动追踪后果？ ≥ 70% 的 playtest 玩家在干预后主动观察目标区域 ≥ 2 个月 增强即时视觉反馈强度；增加因果追溯提示频率
V2 自然后果制衡让玩家感到"干预有后果但不 frustrating" Playtest 观察：玩家是否注意到反噬预警？是否在反噬触发前主动调整干预策略？是否感到反噬公平？ ≥ 60% 的玩家在反噬预警后主动调整策略；≤ 20% 的玩家对反噬感到"不公平" 调整反噬阈值（提高 → 更宽容 / 降低 → 更严格）；增强预警窗口；降低反噬初期严重度
V3 远期后果（3-6 个月后显现）能被玩家归因 Playtest 提问：当远期后果显现时，玩家能否意识到"这与我之前的干预有关"？ ≥ 50% 的远期后果被玩家正确归因 缩短因果链长度（2 个月而非 3-6）；增强因果追溯提示
V4 紧急干预（天降甘霖）能挽救濒危文明 Playtest 观察：当文明面临旱灾崩溃时，紧急干预是否有效扭转局面？ 紧急干预使用后 ≥ 80% 的情况下文明存活 调整紧急干预效果强度或冷却时间
V5 无限干预不导致玩家焦虑或无所适从 Playtest 观察：玩家是否陷入"什么都想干预"的焦虑？是否能自然发展出干预节奏感？ ≥ 60% 的玩家在 30 分钟后发展出稳定的干预节奏（不是每分钟都在干预，也不是完全不干预） 增强反噬预警的引导性；优化事件筛选减少信息过载

7.2 验证时机

  • V1-V5 均在 MVP 原型阶段 验证（3-4 周内）
  • 如果 V1 不通过 → 回到本 GDD 强化视觉反馈与因果追溯
  • 如果 V2 不通过 → 调整反噬阈值与预警机制
  • 如果 V3 不通过 → 强化因果链追踪系统（可能需要缩短因果链或增强 UI 提示）
  • 如果 V4 不通过 → 调整紧急干预参数
  • 如果 V5 不通过 → 优化反噬预警的"软引导"效果，或考虑增加轻度干预频率建议
