文明发展系统 GDD

1. 系统概述（System Overview）

一句话定义：文明发展系统是"经营建设"支柱的承载系统——在连续时间（由 S4 实时时钟+加速驱动）下，以固定步长月级结算 pass（每累计 1 游戏月执行一次，即原 monthly tick 内容，但与玩家回合解耦）自治地推演聚落从远古游群成长为现代都市文明的全部维度（人口/经济/科技/政治/社会/个体/宗教/文化/法律/军事（含战争）/族群（种族）），其演进受生态资源约束、被玩家干预间接引导，从不直接接受指令。

设计目标： - 让"文明凭什么活下来、还能活得更好"（概念文档 2.1 支柱一核心问题）成为一个可被系统模拟的涌现过程，而非脚本化的数值增长。 - 以现实世界文明演进规律为基准（概念文档 R7 / 用户特别指令）：农业剩余→分工→阶层分化→城市→国家→文字/法律制度化→工业化→现代国家；不同文明路径（重农/重牧/重海/重商）产生不同的社会形态、信仰体系与技术路线。 - 贯通古代到现代的完整演进弧线（v1.1.0 核心新增）：文明不停留在古代阶段，而是随时代从原始游群演进到现代都市文明——政治、科技、法律、社会四条主线各有清晰的时代演进路径（2.0 节时代演进框架）。这是概念文档 R6（时代演进内容断裂感）的系统性解法：时代是"生长"出来的，不是"切换"出来的。 - 法律与政治的世俗化路线（v1.1.0 核心变更）：政治合法性来自绩效、共识、血统、制度四项世俗来源；法律从世俗治理需求（纠纷裁决/资源管理/安全维护/契约执行）自然涌现。宗教不授予政权合法性，也不生成法律条文。 - 为 R9（无对手文明的长期动机）提供内生动力——文明自身的复杂化、时代跃迁、文化分化、世代记忆本身就构成长期叙事张力，无需对手文明；军事/战争子系统（§2.10）将「生存对抗」扩展到文明间尺度，为多文明局提供对抗性张力（仍不要求强制对手文明）。 - 实现 S1 定义的 IInterventionTarget 接口（4.1 节），让文明引导/资源投放/灾厄恩赐落在本系统的可干预参数上。

与概念文档的对齐： - 概念文档 3.1.3 定义五大机制（聚落成长/经济/科技树/政治结构/个体生命周期）——本 GDD 扩展为十一大子系统，将宗教、文化、法律、军事（含战争）、族群（种族）纳入完整文明框架（用户指令）。 - 概念文档 R6（时代演进断裂感）、4.4 远景层（古代→中古→近代→现代）、8 版本路线图 v2.0.0/v3.0.0——本 GDD 2.0 节的五时代框架即为这三处的设计落地。 - 概念文档 D4 文明路径分叉、D5 世代记忆累积——本 GDD 机制化。 - 概念文档 4.1/4.2 模块化开关——宗教、文化、法律同样纳入开关框架，但完整设计其逻辑。 - 概念文档 3.1.4 连续时间推进（实时时钟+暂停+加速 1×/2×/5×/20×；底层固定步长月级结算；无玩家回合）——所有时间引用以"连续时间下的固定步长月级结算 pass"为单位。

设计红线： - 文明是自治 AI。玩家通过 S1 干预调节参数（发展倾向权重、粮储系数、科技解锁），但不下达命令、不直接操控个体（概念文档"不下场"原则）。 - 时代不可被直接干预。玩家无法"点一个时代"——时代推进只能通过其前置条件（科技层级/人口/分工深度/治理形态）被间接影响。这是"不下场"原则在时代轴上的延伸。

2. 机制设计（Mechanics）

文明系统为自治系统：由 S4 连续时间驱动，每累计 1 游戏月执行一次固定步长月级结算 pass（原 monthly tick 内容），由 AI 决策驱动。所有子系统共享"文明状态（CivilizationState）"上下文，按结算 pass 推进。2.0 节定义贯穿全部子系统的时代演进框架，2.1–2.11 为十一大子系统（含 §2.11 族群/种族）。

2.0 时代演进框架（Era Progression Framework）— v1.1.0 核心新增

设计理由：概念文档的题材轴是"远古洪荒 → 现代都市"（Logline / 4.4 远景层），但 v1.0.0 的机制设计只覆盖了古代阶段。R6 指出的风险是"时代跃迁产生换了个游戏的断裂感"。本节的解法是：用一套统一的五时代坐标系贯穿全部九个子系统——每个子系统都有自己的时代演进线，各线由同一组门槛条件驱动，因此时代跃迁表现为"多条线同时缓慢生长"，而非"整体切换到新版本"。

enum Era { Primordial, Ancient, Medieval, EarlyModern, Modern }

struct EraState {
    Era current; float progress; int monthsInEra; bool inTransition;
    int transitionMonthsLeft; EraGate nextGate;        // 过渡期剩余(12-24月)/门槛
    float ecoImpactCoefficient; int regressionWatchMonths;  // 生态系数(S2)/倒退观察月数
}

struct EraGate {
    TechTier requiredTier;                 // 主门闩：材料/农具/治理技术层级
    int minSustainedSurplusMonths;         // 连续食物盈余月数（foodSurplus>0）
    float minCapacityUtilization;          // pop / CC(tech,land)；压满「当前科技」承载力
    float requiredDivisionLevel;
    GovernanceType minGovernance;          // 治理形态门槛（≠ TitleTier 头衔）
    LawStage minLawStage;
    bool requiresWriting;                  // 中古门槛起需文字
}
// 已删除：int requiredPopulation —— 绝对人口不得作为时代钥匙（v1.4.4）

承载力定义（与 §2.1 对齐）：

polityCarryingCapacity = Σ settlement.carryingCapacity
carryingCapacity = f(土地/气候, TechTier 农具·作物·水利, 住房·基础设施)
capacityUtilization  = polity.population / max(1, polityCarryingCapacity)

同一绝对人口在不同 TechTier 下意义相反：石器时代大陆级 CC 仅约百万、单文明几万即近天花板；铁器农耕 CC 可达约六千万——五千人几乎无压力。故时代判定读 利用率与盈余，不读裸人头。

时代门槛裁决（v1.4.4 取代 v1.4.3「绝对人口准入线」）——四条铁律： 1. 禁绝对人口门闩：EraGate 不得含 requiredPopulation 或任何「全时代共用/逐级抬高的裸人口阈值」。禁止「石器时代 5000 人进铁器、铁器时代同样 5000 人进王朝」类设计；也禁止用 300/5千/5万/50万 这类绝对下限伪装成「已修正」。 2. 读相对承载力：判定使用 当前 TechTier 下的 capacityUtilization 与 minSustainedSurplusMonths。石器低压满 CC 的部落可晋级古代；铁器下仅数千人、利用率极低的政权不能因「凑够绝对人数」晋级。 3. 三轴正交、互不解锁：Era / TitleTier / ScaleTier 互不推导。进时代 ≠ 升皇帝；人头多 ≠ 换时代；头衔 ≠ 人口带。ScaleTier 仍只服务纳贡/兵力基数（§2.4.5）。 4. 制度深度跟体量+行政走，不跟时代白送：进入中古/近代绝不自动解锁皇帝级大一统行政能力。皇帝级制度深度另需：ScaleTier >= Large（或有效多政体封贡/DominionMode 结构）且行政/治理科技达标。

规则： - 生长而非切换（R6 核心对策）：门槛全部满足后不立即跃迁，而是进入 12–24 月的过渡期。过渡期内 progress 由 0 渐进到 1，新旧并存——旧建筑不消失、旧技术仍可用、旧治理形态逐步让位。 - 多线不同步：十一大子系统各自按本线条件推进，允许错位。错位时 UI/叙事必须同时暴露 Era、TitleTier、ScaleTier，避免玩家误读为「时代=政体等级」。 - 时代倒退：若 科技（知识遗失）/ 分工 / 持续盈余 / 承载力利用率 跌破维持线并持续 24 月，触发时代回退。回退不由绝对人口单独触发。 - 生态耦合：ecoImpactCoefficient 随时代递增写入 S2。TechTier 抬升时 carryingCapacity 重算，利用率可能骤降——属预期行为。 - 实现分层：见 5.4 节——MVP 仅远古→古代最小集，核心层完整古代，中古/近代/现代随版本推进。

2.1 聚落成长（Settlement Growth）

核心逻辑：聚落是人、空间、功能的耦合体。人口受食物盈余与空间承载力驱动；功能区随人口阈值与时代解锁；空间布局受 S2 地貌（水系、坡度、资源节点）约束。

struct Settlement { int id; string name; Vector2 location; int population;
    int carryingCapacity;              // 人口承载力 = f(粮储/住房/空间, TechTier 农具·作物·水利)；随科技跃迁重算（§2.0.2）
    List<FunctionZone> zones; int prosperity;
    int settlementLevel;               // 1营地 2聚落 3村镇 4城邦 5城市 6都市圈
    float growthRate; }                // 月增长率（受食物盈余修正）

enum ZoneType { Residential, Production, Storage, Defense, Civic,         // 全时代
    Religious, Cultural,                 // 古代起
    Industrial, Infrastructure }         // 近代起（工业区高生态压力/路网电力）
struct FunctionZone { ZoneType type; int level; Era unlockedEra;
    float areaCost; float outputMultiplier; float ecoLoad; }  // 生态负荷写入 S2

聚落分档（Settlement Tiers）— v1.4.0 核心新增：

聚落按人口规模分为四档，settlementLevel（1 营地 / 2 聚落 / 3 村镇 / 4 城邦 / 5 城市 / 6 都市圈）与之对应。注意：单聚落不再封顶 5 万——5 万只是「市（City）」档的中段，都市圈（Metropolis）可达千万级；而「国家」是聚合 ≥1 个聚落的政治体（见 §2.12），单聚落 5 万只是其下辖的一个市，远非国家的全部人口。

分档 人口区间 对应 settlementLevel 说明
村 Village ~50 – 2,000 1 营地 / 2 聚落 / 3 村镇 采集狩猎→定居农庄，可见个体
镇 Town ~2,000 – 20,000 4 城邦 城防/文字萌芽，市镇自治
市 City ~20,000 – 1,000,000 5 城市 工业/基础设施解锁，真实城市规模
都市圈 Metropolis ~1,000,000 – 10,000,000+ 6 都市圈 千万级都会；可继续增长至亿级，无硬性封顶

成长规则： - 月级结算 pass：若 foodSurplus > 0 且 population < carryingCapacity，population += population * growthRate（基础 0.02/月，盈余越高越快）。 - 承载力 = min(住房容量, 粮储可持续供养人口, 空间上限)；超承载力→饥饿 debuff→死亡率上升（D2 生存压力螺旋）。近代起 Infrastructure 区大幅提升空间上限（现实世界城市化的机制表达）。 - 阈值解锁（人口 × 时代双门槛，聚落可增长至都市圈不再封顶 5 万）： - ≥ 50 解锁 Production/Storage； - ≥ 200 解锁 Defense/Civic； - ≥ 500 且古代 解锁 Religious/Cultural； - ≥ 1,500 → 升为城邦（Town 档 / level 4）； - 中古 ≥ 8,000 → 升为城市（City 档 / level 5）； - 近代 → 解锁 Industrial/Infrastructure； - ≥ 1,000,000（现代）→ 升为都市圈（Metropolis 档 / level 6）；可继续增长至 10,000,000+，不设硬性上限。 - 注：5 万（50,000）位于「市（City）」档中段，既非封顶也非"国家"——国家由多聚落聚合而成（§2.12）。 - 选址约束（S2 耦合）：聚落必须邻近 water 资源节点；坡度 > 阈值不可建 Production 区；近代起 Industrial 区优先邻近矿脉/水运节点。 - 视觉演进（对齐概念 5.3）：建筑形态随时代变化（茅棚→木构→砖石→工业→高楼），但美术风格全时代统一——时代感来自内容而非画风。

2.2 经济系统（Economy）

核心逻辑：资源在"生产→消耗→储备→贸易→分工"闭环中流转。盈余（surplus）是文明复杂化的燃料——它使部分人口脱离生存劳动，成为工匠、学者、管理者（对应现实文明"农业剩余→分工→阶层"规律）。

enum ResourceType { Food, Material, Luxury, Knowledge, Energy }  // Energy 近代起解锁
struct ResourceStock { ResourceType type; float amount; float monthlyProduction;
    float monthlyConsumption; float reserve; }       // 战略储备（灾年动用）
struct Economy {
    Dictionary<ResourceType, ResourceStock> stocks;
    Dictionary<Occupation, float> laborAllocation;  // 分工：各职业人口占比
    float tradeVolume; float divisionLevel;          // 月贸易量 / 分工深度(0-1)
    ExchangeMode exchangeMode; }                    // 交换形态（随时代演进）
enum ExchangeMode { Reciprocity, Tribute, Market, Monetary, Industrial, ServiceInfo }

时代演进线：互惠共享（远古）→ 贡赋再分配（古代早期）→ 市场与货币（古代末–中古）→ 商业资本（近代）→ 工业生产（近代末）→ 服务/信息经济（现代）。每次形态跃迁提升 tradeVolume 上限与 divisionLevel 天花板。

规则： - 生产消耗 S2 资源：monthlyProduction[Material] 驱动 S2 的 harvestRate[Forest]；monthlyProduction[Food] 受 S2 土壤肥力系数修正（开垦→肥力↓，见 S2 2.4）。全部采集率再乘以 EraState.ecoImpactCoefficient。 - 消耗：每人口每月基础 Food 消耗；Material 用于建筑与工具；近代起 Energy 用于工业区与基础设施，Energy 生产同时产生污染负荷（S2 应力源）。 - 储备：粮储 reserve 低于 20% 触发饥荒预警；紧急干预"生命之泉"直接 +50%（S1 2.3）。 - 分工：当 foodSurplus 持续 3 月为正，divisionLevel 提升，逐步解锁非生存职业（工匠→书吏→学者→工程师）。分工深度是科技、法制、文化解锁的共同前置。 - 贸易：聚落间按比较优势交换资源，提升整体繁荣度，但引入疫病传播风险（D2 关联）。成文法阶段起，契约类规范提升贸易效率（2.9 联动）。

2.3 科技树（Technology Tree）— v1.1.0 全谱扩展

核心逻辑：知识由盈余人口（书吏/学者/工程师职业）按月累积；知识点解锁技术节点；技术改变文明与生态的交互方式——这是 S2 耦合的关键杠杆，也是时代推进的首要门槛。

2.4 政治结构（Political Structure）— v1.1.0 核心重设计

核心逻辑：治理形态随聚落规模、时代与制度积累演进；合法性由四项世俗来源合成。

v1.1.0 变更说明：移除 v1.0.0 的"神权背书 → 政治合法性"耦合（原 legitimacy = religiousEndorsement × 0.5 + 绩效 × 0.5）。合法性公式中不含任何宗教项。宗教仅通过"文化价值观影响民众满意度"这一通用文化渠道间接参与，与艺术、节庆同级，无专属授权通道（2.7 节）。

2.4.4 制度广度：经济/社会制度谱（Institution Spectrum）— v1.3.0 新增

设计理由：决策 #3 将「制度广度」定义为政治 + 法律 + 经济。在九政治形态（§2.4.1）与按国别发展的 LawStage（§2.9）之外，新增经济/社会制度谱作为各国差异化维度——同一政治形态（如王国）下，劳动制、经济形态、行政传统可以完全不同，制造"不同国家有不同制度"的差异化体验。三者与政治形态、时代门槛耦合，并影响经济产出、稳定度、战争动员。

2.4.5 治理层级（统治者尺度）：法理等级 × 体量规模 双维度 — v1.4.2 重写

重写纲领（采纳评审意见）：v1.4.1 将"头衔等级"与"人口规模"绑死，产生大量反例（小朝廷皇帝、郡县制大一统无多王国、法老/可汗非"皇帝"词但属全域最高、国王人口卡死、领主/部族人口重叠、共和城邦缺失）。本版改为两个正交独立维度，互不推导：

  • 维度 A · 法理等级（TitleTier）——按头衔 / 礼制 / 权力来源划分，完全不看人口；
  • 维度 B · 体量规模（ScaleTier）——按政权辖内人口划分，完全不看头衔。
  • 任一统治者 = (法理等级, 体量规模) 的任意组合；同一法理等级可跨任意体量，同一体量可对应任意法理等级。

与 §2.4.3 的关系不变：§2.4.3 是「单个政体自身怎么长」（横向、时代演进）；本节是「多个政体如何上下叠成封贡网络」（纵向）。二者正交。本版双维度模型全时代通用（古代郡县/封建、中古附庸、近代宗主国/保护国、现代霸权/势力范围均适用），不再限定古代。

维度 A · 法理等级（按头衔等级，不绑定人口）

双维度解耦的反例对照（证明头衔≠人口）： - 皇帝级可极小：东罗马后期、后唐、五代小朝廷、南朝陈（人口仅数百万，法理仍为皇帝）；神圣罗马皇帝（直辖领地人口远不足千万，仍持皇帝头衔）。 - 皇帝级可极大：明清/莫卧儿（人口上亿）。 - 非"皇帝"词但属皇帝级法理：蒙古大可汗、波斯沙罕沙、埃及法老、阿拉伯哈里发——其全域最高权威与皇帝同级，仅头衔词不同。 - 国王级可破千万：法兰西/英格兰（巅峰千万级）、波斯独立王国（破千万）——旧"数百万上限"错误。 - 共和·城邦级覆盖古罗马共和、雅典城邦等无君主体系（旧版完全缺失）。 - 游牧大可汗：法理恒为皇帝级，人口因战乱在几十万~数千万间剧烈波动——正因维度解耦才不矛盾。

双法理兼容规则（藩属特例）：一个政权可同时持「对内核皇帝法理 + 对外藩属法理」。例：越南后黎朝对内称帝、对明清称藩王；朝鲜王朝对明称藩、国内行完整行政。故记录 internalTitleTier（内核法理）与 externalTitleTier（对外法理）两个字段，二者可不同；独立政权两字段相等。

数据模型（补全 §2.4.1 第 232 行引用，v1.4.2 重写为双维度）：

enum TitleTier { Emperor, King, Lord, TribalChief, Republic }  // 法理等级（不看人口）
enum ScaleTier { Micro, Small, Medium, Large, Giant, Mega }    // 体量规模（不看头衔）
struct Polity {
    ... // §2.4.1 既有字段
    // —— 治理层级（封贡）字段，v1.4.2 双维度重写 ——
    TitleTier internalTitleTier;  // 对内核法理等级
    TitleTier externalTitleTier;  // 对外法理等级（藩属时低于内核；独立=内核）；独立政权两字段相等
    int? suzerainId;              // 宗主政体 ID；null = 无上级（独立 / 最高）
    List<int> vassalIds;          // 直属附庸政体 ID 列表
    float centralization;         // 中央集权度 (0-1)：高=直辖强、附庸弱；低=分权/封建
    float tributeRate;            // 纳贡率 (0-1)：附庸向宗主上缴比例
    float loyaltyToSuzerain;      // 对宗主忠诚 (0-1)：低→叛乱/独立风险
    ScaleTier scaleTier;          // 体量规模（每结算 pass 由辖内人口自动归类）
}

机制：

  1. 纳贡流（Tribute Flow）：每结算 pass，藩属（即 suzerainId != null 或 externalTitleTier < internalTitleTier）按 tributeRate 向宗主转移资源（Material/Food/Luxury，见 §2.4.4 经济制度谱）。转移量 = 藩属 scaleTier 对应的产出基数 × tributeRate——体量越大，纳贡绝对值越高（解耦后体量维度独立承担"量级"语义）。宗主获调配力加成，藩属被抽取；tributeRate 高 + loyaltyToSuzerain 低 → 推高藩属不稳定度。
  2. 忠诚动态（Loyalty Dynamics）：loyaltyToSuzerain 受宗主 performance/legitimacy（§2.4.2）、中央军力（§2.10 军事）、文化亲缘（§2.8 文化/§2.11 族群）修正；宗主衰败或过度征敛 → loyalty 下降 → 低于阈值触发藩属自立/叛乱（叙事"边地拒绝上缴赋税"/"藩属自立"）。
  3. 继承与分裂（Inheritance & Fragmentation）：皇帝/国王死亡（§2.6 世代传承）→ 继承判定；继承危机叠加藩属 loyalty 低 → 封贡体系解体（帝国→多王国）。即"分久必合、合久必分"。
  4. 体量缺口稳定风险（Scale Gap）：当宗主名义 realm 人口（全帝国之和）≫ 其直辖人口时，centralization 低 → 缺口=分裂风险放大（解释神圣罗马帝国的脆弱）。体量规模维度独立刻画此风险，与法理等级无关。

耦合与红线： - 合法性（§2.4.2）：TitleTier 是合法性权重选择的输入（皇帝级用古代权重 w_p0.40/w_c0.20/w_l0.40；共和国用近代公民权重等）；ScaleTier 体量规模不进合法性公式（延续无神法/纯世俗原则）。封贡附庸忠诚只影响稳定度，不进 legitimacy。 - 时代脱钩（§2.0.2 v1.4.4）：Era 跃迁不改写 TitleTier，也不白送皇帝级行政/封贡深度。皇帝级制度能力另需 ScaleTier >= Large（或有效 DominionMode 多政体结构）+ 行政科技。 - 军事（§2.10）：宗主可征调藩属军力（朝贡/封建义务）；scaleTier 决定可动员兵力基数。 - 族群（§2.11）：多族群帝国的边缘族群易生分离主义，与 loyalty 下降叠加放大分裂风险。 - 不下场红线（S1）：法理等级与封贡关系均为文明自治涌现的派生状态，玩家不可指定——仅可经 devBias_*（如 devBias_military 影响中央军力与封贡维系、devBias_ethnicity 影响族群亲缘与分离倾向）间接影响，绝不下场分封或册立。

MVP / 核心层边界：MVP 单政体起步（玩家文明自身取单一 TitleTier、scaleTier 随人口自动归带，不展开多级封贡）；核心层多聚落/多国家模块 ON 时，封贡全链路（suzerain/vassal/纳贡/分裂）生效。

2.4.5.1 各时代关系形态实例化（古代 / 中古 / 近代 / 现代）— v1.4.3 新增

纲领：维度 A（法理等级 TitleTier）与维度 B（体量规模 ScaleTier）全时代通用、已在 §2.4.5 定义且本节不改动。本节补上第三个同样独立的轴——维度 C · 关系形态（DominionMode）：上下关系用什么制度形式表达。三轴互不推导：

  • A 法理等级 = 我自称什么（头衔/礼制）；
  • B 体量规模 = 我辖内多少人；
  • C 关系形态 = 我与上/下位者以何种制度绑定。

三轴独立性验证（防止旧错误复发）：荷兰共和国 / 威尼斯共和国 = 共和·城邦级法理（A）+ 小型~中型体量（B）+ 条约宗主权（C，海外属地与殖民地）——小体量、非君主、却是宗主。反向：神圣罗马皇帝 = 皇帝级法理 + 中型直辖体量 + 封建附庸关系。关系形态不由体量决定，也不由头衔决定；体量只影响索取的绝对值与维系成本（见机制 1/4）。

关键设计点（现代）：现代国际体系在法理上没有附庸——所有国家主权平等。因此现代层级不能用 suzerainId 硬表达，必须用 asymmetricDependency（事实依附度 0–1）刻画。这正是"取消了藩属，但层级依然存在"的机制表达。

关键设计点（中古）：中古的多重效忠（一位领主同时向两位封君称臣，甚至分属敌对阵营——诺曼底公爵即英王的经典困局）无法用单一 suzerainId 表达，故引入 allegiances 列表。

内部行政层级 ≠ 国际关系形态：现代国家内部的联邦/邦联/自治区，以及古代的郡县、中古的领邦，属于同一政体内部的行政纵深，用 internalTier 表达，不进入 DominionMode（后者只描述政体之间）。这条区分直接回应"藩属是外交臣服关系，不是帝国内部行政区划"。

  5. 解体路径（各时代主路径，接 §2.6 世代 / §2.11 族群 / §2.10 军事）：藩属自立（古代）→ 附庸兼并与王权集权（中古）→ 民族独立运动（近代，由 EthnicNationalism + polarization 驱动）→ 阵营倒戈/中立化（现代）。四条路径均为涌现结果，不预设脚本。
  6. 体量缺口风险（§2.4.5 机制 4）全时代适用：现代形式为"名义势力范围人口 ≫ 直辖人口" → 霸权维系成本（军费/援助占比）随缺口上升，过载则势力范围收缩。

耦合与红线（全部延续，不新增例外）： - 合法性（§2.4.2）：合法性公式仍只吃 TitleTier（近代起叠加 EthnicNationalism w_n）；DominionMode 与 ScaleTier 均不进 legitimacy 公式，只影响稳定度与外交——延续"无神法/纯世俗"原则。 - 军事（§2.10）：各时代动员方式不同（贡军 → 封建征召 → 条约驻军 → 同盟义务），均由 scaleTier 决定兵力基数。 - 法律（§2.9.1）：近代治外法权与殖民地法律移植是 LegalFamily 跨国传播的机制来源（英美法系随殖民扩散），与 S5 legalTraditionSeed 呼应。 - 族群（§2.11）：近代解体路径的主驱动；多族群依附体内的边缘族群分离倾向随 loyalty 下降放大。 - 不下场红线（S1）：玩家不可指定谁向谁称臣、不可宣布保护国、不可让某国加入阵营——三轴状态全部为涌现派生，仅可经 devBias_military（中央军力与维系能力）/devBias_trade（经济依附路径）/devBias_ethnicity（族群亲缘与分离倾向）间接影响。

MVP / 核心层边界：MVP dominionMode = None（单政体，不展开关系形态）；核心层多国家模块 ON 时按当前 Era 启用对应形态。当今地缘政治模式开局直接以 HegemonicSphere / None 初始化（由 S5 提供初始关系）；远古沙盒模式随时代自然演进 TributaryVassalage → FeudalVassalage → TreatySuzerainty → HegemonicSphere——非强制线性，允许跳跃（如从朝贡直接进入条约体系）或长期停滞（"停滞文明"，见 §3.2 边界情况）。

2.5 社会结构（Social Structure）

核心逻辑：盈余产生阶层分化；家族/氏族是关系网载体；阶级流动由分工、战争、教育驱动。反映现实文明"从平权到等级、再到现代市民社会"的演进。

enum SocialClass { Elite, Commoner, Laborer, Outcast }
struct Family {
    int id; string clanName; SocialClass class;
    int wealth; List<int> memberIds;
    float reputation;                  // 声望（影响政治席位）
}
struct SocialStructure {
    Dictionary<SocialClass, float> classRatio;
    List<Family> families;
    float mobilityRate;                // 阶级流动率 (0-1)
    float inequality;                  // 不平等度 (0-1)：写入政治稳定度（2.4）
    float ethnicInequality;           // 族群间不平等 (0-1)：来自 §2.11 EthnicComposition，写入政治稳定度（2.4/2.5）
    float burgherRatio;                // 市民/中间阶层占比（近代起，驱动参政广度）
}

时代演进线：亲属团体（远古，无固定阶层）→ 贵族/平民/依附者分化（古代）→ 封建等级 + 官僚身份（中古）→ 市民阶层与工人阶层兴起（近代）→ 都市市民社会（现代，阶层边界模糊但不平等以财富形式延续）。

规则： - 分化：divisionLevel 提升→classRatio[Elite] 上升，inequality 同步上升。 - 流动：战争胜利→平民可凭军功升阶；贸易繁荣→商人跃升；中古起学院/科举式选拔提供知识型流动；近代起工业与教育大幅提升 mobilityRate 与 burgherRatio。 - 不平等的政治后果（v1.1.0 新增）：inequality > 0.7 且 mobilityRate < 0.2 → 每个结算 pass 扣减稳定度，并压低法律遵从度（2.9 compliance）——这是"阶层冲突"这一长期张力的机制来源（R9 关联）。 - 族群不平等的政治后果（v1.3.0 新增）：ethnicInequality（来自 §2.11 EthnicComposition）> 0.6 且 mobilityRate 低 → 每个结算 pass 扣减稳定度，与 inequality 叠加放大"阶层 + 族群"复合冲突；高 fractionalization 文明若 mixingRate 低则 ethnicInequality 易累积（与 §2.11 耦合）。 - 氏族：个体出生归属氏族，婚姻/继承改变氏族财富（2.6 关系网）。

2.6 个体生命周期（Individual Lifecycle）

核心逻辑：每个 NPC 是带状态机、关系、记忆、情感的 agent。文明是个体聚合的涌现，而非顶层数值。MVP 为骨架版（生—成—死），核心层为完整版。

struct Individual {
    int id; int ageMonths;             // 月龄（在连续时间中逐结算 pass 增长）
    int familyId; float health; float skill;
    Occupation occupation;             // 猎人/农夫/工匠/书吏/学者/工程师/统治者…（随时代扩展）
    float happiness;                   // 受粮储/灾害/文化/信仰影响
    float literacy;                    // 识字度（文字发明后有效，中古起驱动知识产出）
    List<Relation> relations; List<Memory> memories;   // 记忆含创伤/荣耀（D5）
    NeedState needs;                   // 饥饿/安全/归属需求
}
struct Memory {
    MemoryType type;                   // 兽患/丰收/背叛/迁徙/战乱…
    int monthStamp;                    // 发生月龄（编年史锚点）
    float emotionalWeight;             // 情感权重（影响后代叙事）
}

规则： - 生命曲线：出生（父母健康×幸福决定）→ 成长（技能累积）→ 成年（进入分工）→ 衰老（产能↓、死亡率↑）→ 死亡（自然/灾害/战争）。近代起医疗技术延长寿命并压低婴儿死亡率（人口结构随时代变化，现实人口转型的表达）。 - 关系与记忆：记忆跨代遗传（D5）——某家族三代前的兽患记忆使其对森林态度负面，影响该家族执政时的政策倾向（AI 决策输入）。 - 职业由分工（2.2）、阶级（2.5）与时代（2.0）共同决定；书吏/学者是知识产出的人力基础，祭司是宗教系统（2.7）的人力基础。 - 幸福度：粮储足 + 无灾害 + 节庆 → 高；大旱/战乱/法律不公 → 低 → 可能出走或参与动荡（稳定度↓）。

2.7 宗教系统（Religion System）— v1.1.0 定位调整

设计定位（v1.1.0 变更）：宗教保留为文明十一大子系统之一（用户明确要求），但定位为文化/信仰维度——它塑造世界观、节庆、伦理观念与个体心理。宗教不授予政治合法性（2.4），也不生成法律条文（2.9）。 原 v1.0.0 的"四维耦合"删去"政治合法性"与"伦理与法律"两维，保留"战争与冲突"与"资源与生态"，并明确"文化与个体"为宗教的主渠道。

2.7.1 宗教的起源与演进（独立文化线）

宗教不是初始存在的，而是随文明复杂化涌现的。演进阶段对应现实文明宗教史，且贯通到现代：

阶段 时代 触发条件 特征 现实参照
自然崇拜 (Animism) 远古 聚落初期，对不可控自然（雷/河/兽）的敬畏 万物有灵，无专职祭司，口头禁忌 狩猎采集部落
祖先崇拜 (Ancestor) 远古末–古代初 个体记忆累积 + 氏族形成 祭祀先祖祈福，氏族长老兼祭司 东亚宗法、罗马家神
多神教 (Polytheism) 古代 分工出现祭司职业 + 农业周期固化 神祇统辖自然/丰收/战争，神庙建成 古希腊/美索不达米亚
主神/一神教 (Henotheism→Monotheism) 古代末–中古 聚落网络扩大 → 神祇谱系融合（贸易/移民带来的信仰整合） 至高神统摄众神，信仰跨聚落统一 大区域文明的信仰整合
伦理宗教 (Ethical) 中古 文字 + 哲学反思 + 集体苦难经验（疫病/战乱） 信仰与伦理/来世绑定，经文制度化 佛教/基督教/儒教化
世俗多元 (SecularPluralism) 近代–现代 学术兴起 + 现代法系 + 都市化 信仰成为个人选择，多信仰共存，adherence 下降但不归零 现代社会的宗教处境

注：主神/一神教的触发条件在 v1.1.0 中已从"王国形成 + 神权背书需求"改为"聚落网络扩大导致的神祇谱系融合"——去掉了政治授权动因，改为文化融合动因。

struct Deity { int id; string name; Domain domain; float popularity;
    float culturalReach; }            // culturalReach 替代 v1.0.0 的 stateEndorsed
struct Religion { FaithStage stage;
    List<Deity> pantheon; List<int> priestIds; List<HolySite> holySites; List<Ritual> rituals;
    EthicalOutlook outlook;            // 伦理观念→输入文化价值观(2.8)，非法律来源

2.7.2 宗教对文明的影响（一主渠道 + 两项耦合）

  1. 【主渠道】文化与个体：outlook 输出伦理观念（如"敬老""不可滥伐圣林"），作为文化价值观注入 Culture.traits（2.8）；仪式与节庆提升 happiness 与凝聚力；信仰为个体在灾难中提供心理支撑（降低灾后 happiness 跌幅）。这是宗教的主要作用面。
  2. 战争与冲突（保留）：教义差异 → 教派分裂（schismRisk）；异信仰聚落可能被视作威胁 → 自发宗教性冲突（v1.1.0 战争系统雏形，玩家可影响不可指挥）；圣地争夺是战争动机之一。但宗教不是政权正当性的来源——冲突动因是身份与圣地，而非"神授王权"。
  3. 资源与生态（保留）：圣林/圣泉受宗教保护 → 降低该地 harvestRate（生态保育的宗教动因）；祭祀消耗 Luxury/Food 储备（文明成本）。

明确解耦（v1.1.0）：① 宗教不进入 Polity.legitimacy 公式；② 宗教不生成 Norm；③ 宗教的伦理观念只能经由"文化价值观"这一公共通道影响法律遵从度（compliance）——即民众更愿意遵守与自身价值观相符的法律，但法律条文本身出自世俗治理需求（2.9）。

2.7.3 玩家干预如何影响宗教

玩家不直接创教，但可通过 S1 文明引导注入"信仰倾向"权重，间接塑造宗教演进方向： - 文明引导"农业倾向"持续 → 自然崇拜向"丰收神"聚焦，加速多神教。 - 文明引导"防御倾向" → 战神信仰崛起（影响文化特质"尚武"，不影响政权授权）。 - 灾厄"疫病"频繁 → 民众转向"治愈神/伦理宗教"（对现世苦难的宗教回应）。 - 恩赐"灵感" → 可能触发"神迹记忆" → adherence 跃升、新圣地生成。 - 反噬（S1 2.1）：同聚落 6 月内注入 ≥ 3 种信仰倾向 → 宗教混乱（schismRisk↑、稳定度↓）。

2.8 文化系统（Culture System）

核心逻辑：文化是一个文明的"签名"——艺术、节庆、口述传统、文字、文化特质，由文明路径与环境内生生成（用户指令"文化特质生成"），与宗教（2.7）、个体记忆（2.6）交叉滋养。文化价值观是宗教伦理与世俗经验的汇流处，也是它影响法律遵从度的唯一通道。

struct CulturalTrait { string id; string name;   // 如"崇水""尚武""重商""重法"
    TraitCategory category; float intensity; int originMonth; }  // 特质强度/诞生月龄
struct CultureProfile {                 // v1.3.0 新增：跨国文化家族签名
    string languageFamily;             // 语言家族（与族群 EthnicGroup.languageFamily 同源）
    string aestheticTradition;         // 审美/艺术传统
    SocialStructureOrientation socialStructureOrientation; // 社会结构取向（宗族/阶级/个人主义）
    List<ValueAxis> coreValueAxes;     // 核心价值轴（集体主义↔个人主义、尚武↔尚文、重农↔重商…）
}
enum SocialStructureOrientation { LineageClan, ClassHierarchy, Individualist }
struct Culture {
    CultureProfile profile;            // v1.3.0：每个文明独立文化签名
    List<CulturalTrait> traits; List<Artwork> artworks; List<Festival> festivals;
    bool writingInvented;              // 文字是否诞生（中古门槛前置）
    OralTradition oralTradition; ValueProfile values; }  // 价值观：宗教伦理+世俗经验+环境

规则： - 特质生成：环境塑造价值（近水→"崇水"；多兽患→"尚武"）；经济形态塑造取向（贸易繁荣→"重商"）；成文法长期稳定运行→"重法"（v1.1.0 新增：制度经验也能沉淀为文化）；宗教塑造审美与伦理。 - 节庆：绑定 S2 四季（春播祭/秋收庆/冬藏节）与宗教仪式，提升 happiness 与凝聚力（稳定度+）。现代时代节庆世俗化（国庆/纪念日与宗教节庆并存）。 - 文字：divisionLevel 高 + 政治复杂 → 自动"发明文字" → 编年史从口述升级为可考文本（R4 叙事可读性、D5 记忆固化），并成为中古时代门槛的必要条件。 - 艺术：繁荣度高的文明产出 artworks，成为视觉差异化（概念 5.3 文明演进表达）。 - values → 影响法律 compliance（2.9）、个体 happiness、政治共识项（与艺术/节庆同级的通用渠道，无宗教专属加成）。 - 跨国文化家族（v1.3.0 新增）：每个文明持有独立 CultureProfile（语言家族/审美传统/社会结构取向/核心价值轴），由环境/经济/宗教/族群（§2.11）共同塑造，但每个文明有独立签名，不是通用涌现——即便同处古代、同是王国，两文明的审美传统与核心价值轴也可截然不同。Culture.traits/values 的既有生成机制作为底层，CultureProfile 是其上层的"文明签名"聚合（保留 v1.1.0 的 values/traits 生成机制不变）。

2.9 法律与制度（Law & Institutions）— v1.1.0 核心重设计

核心逻辑：法律从世俗治理需求中自然涌现——当聚落反复出现纠纷、资源争夺、治安事件与交易违约时，治理者被迫产出规范。法律随时代从口头习惯法演进到成文法典，再到现代分权法系。

v1.1.0 变更说明：移除 v1.0.0 的"早期 norms 全部 Religious（神法即最早的法律）"设定。NormSource 枚举中不含宗教项。宗教伦理只能经由文化价值观影响法律的遵从度，不生成法律条文（2.7.2）。

enum LawStage { Customary, Codified, ModernLegalSystem }
enum LegalFamily { CivilLaw, CommonLaw, SocialistLaw, CustomaryLaw }  // 法律传统渊源家族：与 LawStage（成熟度）正交
enum NormSource { Dispute, Resource, Security, Contract }        // 四类世俗治理需求
enum NormDomain { Civil, Criminal, Property, Procedural, Constitutional }

struct Norm { string description;      // 如"盗窃者偿三倍""水源林禁伐"
    NormSource source; NormDomain domain;
    float compliance;                  // 遵从度(0-1)：文化价值观+执法+公正性
    int originMonth; bool isWritten; } // 是否已成文（文字发明后）
struct LawCode { LawStage stage; LegalFamily lawFamily; List<Norm> norms;
    float enforcement;                 // 执法力度(0-1)：官僚深度/稳定度
    float impartiality;                // 公正性(0-1)：阶级差别适用与否
    List<int> courtIds; bool separationOfPowers; }  // 裁判席/官署/法院 / 权力分立(现代)

法制演进三阶段：

阶段 时代 形态 裁决者 触发条件
习惯法（Customary） 远古–古代初 口头习俗与判例记忆，无成文条文 长老 / 首领 月纠纷事件数超阈值，且聚落人口 ≥ 50
成文法（Codified） 古代末–中古 王室法典 / 城邦法条，刻写公示 官署法庭 文字已发明 + 官僚深度 ≥ 1 + 王国/帝国形态
现代法系（ModernLegalSystem） 近代–现代 宪法 / 民法 / 刑法 / 程序法分离 独立法院 民族国家 + 制度合法性 ≥ 0.4 + 参政广度 ≥ 0.3

规则： - 规范由治理压力涌现：每个结算 pass 统计四类压力（纠纷事件数 / 资源争夺事件 / 治安事件 / 交易违约），任一类超阈值 → 生成一条对应 NormSource 的 Norm（描述由 AI 按情境生成）。例：连年争水 → Resource 类规范"上游不得断流"；商路兴起后违约频发 → Contract 类规范"契约需两名见证"。 - 环保类法律的世俗来源：如"水源林禁伐"由 Resource 压力催生（水土流失的教训），而非宗教禁忌——宗教的圣林保护是另一条独立通道（2.7.2 第 3 项），两者可并存但机制不同。 - 法律效果：降低内部冲突（稳定度 +）；提升契约与贸易效率（2.2 tradeVolume +）；规范资源使用（写入 S2 harvestRate 上限）；成文法与现代法系供给 Polity.sources.institution（2.4 唯一制度合法性来源）。 - 公正性与阶层：impartiality 低 → 底层 compliance 下降 → 与 inequality（2.5）叠加放大阶层冲突；现代法系要求 impartiality ≥ 0.5，否则制度合法性项受损（现代分支的宪政危机机制）。 - 遵从度合成：compliance = f(enforcement, impartiality, cultureValueCongruence)——文化价值观与规范契合度越高，民众越自愿遵守（宗教伦理经此通道间接生效）。

2.9.1 法律体系家族（Legal Family）

① 它是什么：除按成熟度阶段（LawStage：习惯法→成文法→现代法系）演进外，法律还按历史传统渊源区分出四大法系家族——大陆法系（Civil Law）、英美法系（Common Law）、社会主义法系（Socialist Law）、习惯法（Customary Law）。家族是"这国法律从哪路传统长出来"，独立于成熟度阶段——一个现代国家可以是大陆法系也可以是英美法系，两者都可达现代法系阶段。

② 与 LawStage 正交：LawStage = 成熟度（法律"多发达"）；法系家族 = 传统渊源（法律"从哪路传统来"）。二者正交——同一 LawStage 可挂不同家族（如现代法系既可是大陆法系也可是英美法系），同一家族可跨多个 LawStage（如大陆法系可处于成文法阶段也可处于现代法系阶段）。现有 LawStage 三阶段演进（§2.9）保留不变，法系家族是叠加在成熟度之上的"传统渊源"维度。

③ 四大家族含义： - 大陆法系（CivilLaw）：以成文法典为最高法源、法官依法典裁判的传统（欧陆为典型）。 - 英美法系（CommonLaw）：以判例与习惯为法源、法官可"造法"的传统（英美学圈为典型）。 - 社会主义法系（SocialistLaw）：以成文宪法与计划经济法令为骨架、强调国家计划的传统（20 世纪社会主义国家为典型）。 - 习惯法（CustomaryLaw）：以长期习俗与社群规范为法源、无统一法典的传统（众多非国家社会为典型，亦与 §2.9 习惯法阶段同源，但此处指家族层）。

④ 延续"无神法"原则：四大家族均为世俗传统渊源，宗教法不进入合法性公式（与 §2.4 四项世俗来源、§2.7.2 解耦一致）。即便未来加入"宗教法家族"，也仅为描述性标签（记录该文明法律受宗教传统影响），绝不构成合法性授权或法律条文来源——宗教经此通道仍只可经文化价值观影响 compliance（§2.9 遵从度），不生成 Norm。

⑤ 初始化规则（v1.3.1 新增）： - 地缘模式（当今地缘政治）：mode == ModernGeopolitics 时，由 S5 WorldInitConfig.legalTraditionSeed（按起始区域在真实/历史法律传统分布中映射的典型家族）初始化 lawFamily——如欧洲→大陆/英美、前苏东→社会主义、部落区域→习惯法；玩家可在 New Game 设置中可选"法律传统偏好"偏置该映射，但绝不指定某具体国家的家族。 - 沙盒模式（远古沙盒）：mode == PrimordialSandbox 时不预设家族，lawFamily 随政治形态/文化/时代门槛涌现——官僚制 + 成文法倾向 → 大陆法系；判例传统的海洋文明 → 英美法系；计划经济 + 近代革命 → 社会主义法系；并在进入近代 + 民族国家后趋于锁定（此后家族基本固定，仅极端政权更替可变更）。

⑥ 耦合与效果（v1.3.1 新增）：法律家族与多子系统耦合，影响治理与经济的若干指标—— - 政治：近代宪政 / 权力分立与大陆 / 英美法系更相容（其 separationOfPowers 与本族成文 / 判例传统契合）。 - 文化：CultureProfile 核心价值轴影响 compliance（家族传统与民众价值契合度越高，遵从度越高）。 - 制度谱：官僚制 / 世袭制倾向影响 impartiality 与成文倾向（官僚制更推成文，与大陆法系互相强化）。 - 经济：大陆 / 英美法系提升契约执行与贸易效率（tradeVolume +）；习惯法区域贸易半径受限；社会主义法系在计划经济指令下贸易形态不同。

法律家族始终为文明自治派生状态，玩家仅经 S1 间接参数与 New Game 真实地理种子影响，绝不"下场"指定某国家族——与 §1 红线一致。

2.10 军事/战争子系统（Military / War Subsystem）— v1.2.0 新增（并入 S3，非独立 S11）

设计理由：概念文档 v1.3.0 将「军事」明确列为「生存对抗」支柱的文明间表达；用户指令要求军事作为文明级抽象能力，玩家在战略层只引导军事方针/军备方向（间接），战争由系统在地图上自动结算，绝不出现 RTS 式直接指挥。因此军事并入 S3 作为第十子系统，而非独立 S11。军事/战争子系统在核心层即可用：当「多聚落」模块 ON 时，文明间即可在地图上自动开战（MVP 单聚落时仅被动应战、无主动开战 AI）；不再严格限定于延展层——与概念文档 v1.3.1 §4.3 对齐（延展层 v1.1.0 文明间关系在此基础上深化外交/联盟/吞并）。

2.10.1 军事作为文明能力（MilitaryState）

每文明（及主要聚落）持有 MilitaryState：

struct MilitaryState {
    float militaryPower;     // 军力（可动员战力总和，战力点；= 征召人口 × 装备系数）
    int militaryTechLevel;   // 军事科技等级（已解锁的最高「军事/防御」主干线节点对应的 TechTier）
    float defenseLevel;      // 防御等级（城防/要塞，0-1，衰减敌方进攻有效系数）
    bool hasNavy;            // 是否拥有海军（仅沿海文明可达，由真实地理 S5 判定）
    WarStatus warStatus;     // 和平/动员/交战中/战败/战胜
    float warWeariness;      // 战争疲劳（累计，写入政治稳定度修正）
    int supplyMonths;        // 补给可维持月数（由军费/粮储驱动，归零→战力衰减）
}
enum WarStatus { Peace, Mobilizing, AtWar, Defeated, Victorious }

军力积累（每个结算 pass）：militaryPower += levyPopulation × equipFactor(militaryTechLevel) × growthRate（受征召上限约束，征召过多 → 劳动力↓ → 生产↓，见 2.2 经济耦合）。海军仅当文明含沿海聚落（S5 真实地理判定 hasCoast）且已解锁相应军事科技（T3 城防起）时 hasNavy = true。

时代耦合：军事能力随时代自然增强——远古游群仅有临时征召（木石兵器，militaryTechLevel=T1）；古代王国拥有常备军与城墙（T3）；中古工程筑城与攻城器械（T5）；近代火药（T6）；现代工业战争（T7/T8）。这与 2.0 时代框架一致：战争形态是时代演进的副产物，而非独立开关。

2.10.2 科技树「军事/防御」主干线（第七主线，补全 2.3）

在 2.3 科技树新增第七主干线「军事/防御」，跨时代累积（与六条既有主线同构），节点解锁即写入 MilitaryState：

主干线 T1–T2 远古 T3–T4 古代 T5 中古 T6 近代 T7–T8 现代
军事/防御 木石兵器、陷阱 铜兵、城墙、城防 工程筑城、攻城器械 火药、火器 蒸汽铁甲、机枪 / 信息战、导弹

节点效果（示例）：城墙 → defenseLevel += 0.3；火药 → militaryTechLevel 跳至 T6 等效；信息战 → 现代战争指挥效率。军备方向由玩家 devBias_military 间接引导（见 2.10.4），文明按环境自主决定解锁顺序。

2.10.3 战争/冲突：作为「生存对抗」的文明间表达

战争的动因来自文明自身的对抗性张力，与既有子系统耦合：

  • × 政治（2.4）：王国/帝国（中央调配力强）更易发动扩张战争；战败（stability↓ 跌破阈值）可能触发政权更替/动荡事件（2.4 政权更替表按时代呈现）。
  • × 经济（2.2）：军费每个结算 pass 消耗 Material/Food/Luxury 储备 → 压缩 surplus → 压低 divisionLevel（「穷兵黩武」长期削弱文明复杂化）；军力征召抽离劳动力 → 生产↓。
  • × 宗教（2.7.2，已耦合）：教义差异/圣地争夺 → 自发宗教性冲突；「圣战」作为战争动机之一（信仰动因，非政治授权）。
  • × 族群（§2.11，v1.3.0 新增）：EthnicComposition.polarization 高 → 内战动因（文明内部族群冲突）与文明间战争概率上升；多族群帝国的边缘族群易生分离主义，触发内战（同军费/稳定度/生态通道，与文明间战争并列）。族群战争由文明 AI 基于 polarization/fractionalization 自主爆发，玩家仅经 devBias_ethnicity 间接影响，绝不下场指挥。
  • × 生态（2.3/S2）：战争破坏环境——战场 harvestRate[Forest/Soil] 下降、聚落焚毁、人口流离 → 写入 S2 应力源（与 E3 现代生态回旋同通道）。

2.10.4 战略层：玩家经 S1 间接引导（不下场）

玩家不指挥任何部队。通过 S1 文明引导注入「军事/战争方针」方向，写入 S3 devBias_military（与 devBias_agriculture 等并列，聚落级，3-5 月衰减）：

  • devBias_military > 0（尚武/扩张倾向）：AI 决策权重偏向优先解锁军事科技、提高征召比例、更易接受开战决策。
  • devBias_military < 0（守势/城防倾向）：AI 偏向优先提升 defenseLevel、降低征召、回避主动开战。
  • 反噬同 S1——同聚落 6 月内注入 ≥ 3 种含军事的冲突倾向 → 决策混乱（S1 2.2.5）。

2.10.5 战斗自动结算模型（地图演示，非 RTS）

战争由系统检测触发（动因见 2.10.3），在地图上自动结算并演示（S8 可视化军队移动/攻城/战线），玩家不可介入单位级。结算为状态机 + 简版胜负公式：

// 参战有效战力（每方）
effPower_A = militaryPower_A × techFactor(milA) × supplyFactor(supplyMonths_A) × moraleFactor(warWeariness_A)
effPower_D = militaryPower_D × techFactor(milD) × supplyFactor(supplyMonths_D)
           × (1 - defenseLevel_D × terrainDefenseBonus)   // 防守方受城防与地形衰减

// 海军修正（仅跨水域作战）：进攻方无海军而目标为沿海 → effPower_A ×= 0.3（两栖劣势）
// 地形修正（S5 真实地理）：山地/河流天险 → terrainDefenseBonus 上升

// 胜负判定（每月结算一次战役步骤）
ratio = effPower_A / effPower_D
if ratio > WIN_THRESHOLD (e.g. 1.5): 进攻方推进/破城 → warStatus 趋 Victorious
elif ratio < 1/WIN_THRESHOLD:       进攻方溃退 → Defeated
else:                               拉锯 → 双方持续消耗 supplyMonths 与军力（warWeariness↑）

// 战损写入
casualtyScale = clamp(|effPower_A - effPower_D| / max(effPower_A, effPower_D), 0, 1)
militaryPower_A *= (1 - casualtyScale × LOSS_RATE)
// => 经济：粮储/材料消耗；生态：S2 harvestRate↓（战场破坏）；政治：stability 受 warWeariness 修正

设计红线（与「不下场」一致）：玩家永不指定进攻目标、调动部队或下令交战；开战决策由文明 AI 基于动因（政治/经济/宗教/资源）自主做出，devBias_military 仅偏移其权重。战争的全部单位级过程由系统演示，玩家是旁观者（与 2.7.2 宗教战争、概念文档 2.2 支柱二（文明间战争）「战争应是文明自发的，玩家可影响但不能指挥」一致）。

2.11 族群/种族子系统（Ethnicity Subsystem）— v1.3.0 新增（第十一子系统）

设计理由：决策 #1 将「种族」定为真实民族种子。在「当今地缘政治」模式用真实民族/语系分布（汉藏、印欧、闪米特、班图、南岛、乌拉尔、尼日尔-刚果等）作初始化种子；在「远古沙盒」模式，民族由游群分裂、迁徙、环境隔离涌现分化。族群是文明差异化的核心维度之一——不同国家/文明有不同民族构成、语言家族与文化底色，且承载政治（民族自决/民族主义）、军事（族群极化→内战）、文化（语言家族）、社会（族群不平等→稳定度）等多处耦合。

2.11.1 数据模型

enum LanguageFamily { SinoTibetan, IndoEuropean, Semitic, Bantu, Austronesian, Uralic, NigerCongo, ... }
    // 主要语系（数据集驱动，可扩展；地缘模式引用真实语系，沙盒模式由分化涌现）

struct EthnicGroup {
    int id;

}

struct EthnicComposition {
    List<EthnicGroup> groups;
    float dominanceIndex;            // 主导度 = max(populationShare)（0-1）
    float fractionalization;         // 族群碎片化指数（0-1，越高越多元/越易极化）
    float polarization;              // 族群极化度（0-1，月度更新；战争动因之一，§2.10.3）
    float ethnicInequality;          // 族群间不平等（0-1，写入政治稳定度修正，§2.5）

}
struct EthnicSeedEntry { LanguageFamily family; string name; float share; Vector2 region; }

2.11.3 与既有子系统耦合

  • × 政治（§2.4）：近代民族国家可携带 EthnicNationalism 合法性变体——当 Polity.type ∈ {NationState, ModernRepublic} 且 dominanceIndex 较高时激活，向合法性公式叠加一项“民族自决/认同”加权（与既有四项世俗来源并存，不替代，权重 w_n 为暂行值，详见 §2.4.2）。多族群且 polarization 高时，民族自决诉求可能引发分离/动荡事件。
  • × 军事/战争（§2.10.3）：polarization 提升开战概率与内战动因——高 fractionalization + 低 mixingRate 的文明内部更易爆发族群冲突（文明间战争之外的新动因），内战消耗同军费/稳定度通道。
  • × 文化（§2.8）：族群承载 languageFamily 与部分文化特质（traits），是 CultureProfile.languageFamily 与底层 Culture.traits 的来源之一；不同族群带来不同语言家族 → 文化签名差异。
  • × 社会（§2.5）：ethnicInequality 写入政治稳定度（扩展 §2.5）——族群间不平等叠加阶级不平等，放大冲突与稳定度压力。

2.12 国家 / 政体聚合（Polity Aggregation）— v1.4.0 核心新增

核心逻辑：文明在「单聚落封顶 5 万」的旧尺度下，国家与聚落几乎同义。v1.4.0 将模拟量级提升到真实世界——国家（Polity / NationState）是聚合 ≥1 个聚落的政治体，其人口 = 下辖所有聚落人口之和：

struct Polity {                       // 沿用 §2.4.1，新增聚合字段

王国 / 帝国 数万~数千万 聚合数至数十个聚落
民族国家 数百万~数亿 多聚落/多区域统合
现代共和（大国） 数千万~十亿+ 如中华级 ~1.4B、次大陆级 ~1B+

明确边界（回应"5 万不是国家"）：单聚落 5 万（50,000）只是「市（City）」档的中段，是一个市的人口；而「国家」是聚合体，下辖可能包含数十个乃至上千个聚落，总人口达千万~十亿级。聚落分档（§2.1）与国家治理形态（§2.4.3）是两个不同尺度的概念——前者描述单聚落规模，后者描述聚合政体的规模与形态。

模拟策略（呼应 §6.1 CV4「人口分层聚合模拟」）： - 聚落层：跑个体/代理微观模拟（村~市看得见人，关键个体带状态机/关系/记忆）。 - 国家层：仅做聚合统计（总人口 / 总产出 / 总军力 / 稳定度），不逐个模拟国民——避免"千万人口逐 NPC"的性能灾难（T1/T4 关联）。国家层是统计视图，其数值由各聚落微观模拟汇总而来，自身不产生新的个体级行为。 - 这一分层使 S3 既能呈现"单聚落微缩沙盒"的可见个体，又能承载真实量级的多聚落国家，且性能可控。

与干预系统的耦合：玩家经 S1 注入的 devBias_* 仍异步、延迟生效（由 S4 连续时间驱动），写入各聚落的 AI 决策参数（§4.1）；国家层聚合数值随之在后续结算 pass 中自然反映，玩家绝不指挥具体国民或部队（全局"不下场"红线，§1）。

3.1 预期涌现行为

D4 — 文明路径分叉（Civilization Path Divergence）

同初始条件，因玩家引导倾向（农业/狩猎/航海/商业）不同，文明走上不同路径：农业路径→灌溉技术线→丰收信仰→宗法社会→王国→帝国；狩猎路径→驯化线→祖先/战神信仰→平权氏族→长老会→议事城邦；航海路径→渔业/造船→重商城邦→近代港口工业。分叉在时代跃迁时被放大而非收束——两条路径进入近代时的工业形态完全不同。

D2 — 生存压力螺旋（Survival Pressure Spiral）

大旱→粮产↓→粮储消耗→饥饿→劳动力↓→生产再↓→人口死亡→分工崩塌→学者/工匠流失→科技与文化衰退→可能触发时代倒退（2.0.2）。文明引导（S1）或紧急干预可打断此螺旋。

D5 — 世代记忆累积（Generational Memory）

三代前兽患记忆→某家族对森林负面态度→该家族执政时限制伐木（生态保育的"历史惯性"源）。记忆使世界有纵深而非每次重置。

R7 — 文化特质涌现

长期重农 + 丰收信仰 → "崇土重农"特质固化 → 影响后代政策（优先粮储、轻视贸易）。成文法长期稳定运行 → "重法"特质 → 提升后世法律遵从度。文化成为长期动机的一部分，缓解 R9。

E1 — 时代跃迁的渐进生长（Era Growth）— v1.1.0 新增，R6 首攻

门槛达成后进入 12–24 月过渡期：先是几座砖房出现在夯土屋之间，接着官署替代长老议事的空地，然后旧仓储区被改建。玩家体验到的是"我的文明在长大"，而不是"游戏进入了第二章"。多线错位（科技已达中古但政治仍是王国）进一步模糊了跃迁边界——这正是 R6 的解法。

E2 — 合法性重心迁移（Legitimacy Shift）— v1.1.0 新增

古代靠血统维系的王朝，进入近代后血统权重降至 0.2，若该文明未积累制度合法性（无统一法典、无常备官僚），合法性总值将随时代跃迁而自动下滑——不是因为玩家做错了什么，而是因为"旧的正当性理由在新时代不够用了"。这会自发催生革命事件。政治现代化因此成为一道必须主动经营的坎，而非自动奖励。

E3 — 现代生态回旋（Modern Ecological Boomerang）— v1.1.0 新增

近代工业化 → ecoImpactCoefficient 升至 1.0+ → 森林与水质进入 S2 应力区 → 若文明继续扩张则触发不可逆相变 → 农业产出崩塌反噬工业人口。文明必须用 T8 的环境治理技术自我修正，否则崩溃。现代阶段的挑战不再是"如何发展"，而是"如何在自己改造过的世界里活下去"——这是概念文档 4.4 现代生态问题的动力学核心。

E4 — 文明间战争（War as Inter-Civ Survival Adversarial）— v1.2.0 新增

两个文明因资源争夺/圣地冲突/扩张欲而开战 → 系统在地图上自动结算 → 胜方吞并边区或索取贡赋，败方稳定度骤降可能触发动荡 → 战争破坏环境（S2 应力）→ 双方长期承受军费与战损。玩家只通过 devBias_military 偏移双方的尚武/守势倾向，不指挥任何一场战斗。战争使「生存对抗」从「文明 vs 自然」扩展到「文明 vs 文明」，本身即叙事素材（S6 战争编年）。

4.1 IInterventionTarget 接口实现

S3 实现 S1 定义的 IInterventionTarget，注册可被干预的文明参数：

class CivilizationSystem : IInterventionTarget {
    Dictionary<string, CivParameter> registeredParameters;

    void RegisterInterventionParameter(string paramKey, float defaultValue, float min, float max) {
        registeredParameters[paramKey] = new CivParameter(defaultValue, min, max);
    }
    void ApplyIntervention(string paramKey, float deltaValue, int durationMonths) {
        CivParameter p = registeredParameters[paramKey];
        p.pendingDelta += deltaValue;
        p.remainingDuration = durationMonths;   // 文明引导倾向衰减（S1 2.2.5: 3-5 月衰减）
    }
    float GetParameterValue(string paramKey) { return registeredParameters[paramKey].currentValue; }
}

文策渊注（v1.1.0）：本次修订的三个核心动作是接上时代轴、政治与法律世俗化、宗教归位文化。

① 时代轴：v1.0.0 的问题不是设计错了，而是只设计到了古代——一份只覆盖古代的文明 GDD 会让 R6 在进入 v2.0.0 时以"结构性重构"的形式爆发。2.0 节的五时代坐标系与其说是新增内容，不如说是给九个子系统各装上一根贯通到现代的轨道：TechTier 从 4 级扩到 8 级、LegitimacySource 一次设计四项、LawStage 一次设计三阶段——结构现在就位，中古与近代才只是"填内容"而非"改地基"。这是 R6 的技术层解法；体验层解法是 12–24 月过渡期与多线错位（E1），需在 MVP 用 V6 验证。

② 世俗化：移除"神权背书→合法性"与"神法即最早法律"两处耦合后，政治与法律各自获得独立演进逻辑——合法性从"个人"（血统/魅力）迁移到"制度"（法典/程序），法律从治理压力涌现而非从教义降临。意外收益是 E2：古代靠血统立国的王朝，进入近代会因血统权重降至 0.2 而自动陷入合法性危机，使"政治现代化"成为必须主动经营的坎（R9 长期动机的新来源）。

③ 宗教归位：宗教保留为九子系统之一，主渠道改为文化与个体心理。风险在 CV2——解耦后是否退化为装饰。我判断不会：圣地生态保育、教派冲突动因、灾后心理支撑、文化特质塑造这四处足以让玩家感到它在起作用，但需 V4 的新增提问来证伪。

主要设计赌注仍是 R6 的体验层解法：时代必须让玩家感到"我的文明长大了"，而不是"游戏进入了第二章"。若 MVP 的远古→古代单次跃迁就被感知为"切换"，则需在实现中古前重新设计过渡机制。
