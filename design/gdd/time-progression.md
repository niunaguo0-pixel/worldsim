# 时间推进系统 GDD（S4）

## 1. 系统概述（System Overview）

**一句话定义**：时间推进系统是 WorldSim 的"心跳"——世界跑在连续实时时钟上（可暂停、可 1×/2×/5×/20× 加速），玩家没有"回合"概念；底层为性能保留一个固定步长月级结算（accumulator：每累计 1 个游戏月执行一次"结算 pass"，即原 monthly tick 的全部内容），驱动 S2 生态结算与 S3 文明结算；玩家干预进入 pending 队列，按延迟在连续时间中异步生效。

**设计目标**：
- 让世界"自己往前走"——玩家暂停观察、随时干预、随时加速，但世界不依赖玩家的"结束回合"指令才推进（去除月历回合制的回合边界）。
- 在"连续实时感"与"模拟可预测性/可重放性"之间取得平衡：表现层是连续时钟，模拟层是固定步长（deterministic monthly pass），二者通过 accumulator 解耦。
- 提供时间尺度跃迁（Scale Leaping）：个体级 ↔ 聚落级 ↔ 国家/文明级 ↔ 世代级 的 LOD 切换，让单聚落微缩沙盒与千万~十亿级国家聚合在同一套时间系统下共存。
- 承载世代传承的连续生命周期：个体 ageMonths 在连续时间中增长，越过阈值触发死亡/继承；文明级"世代"由关键人物更替或制度惯性定义。

**与概念文档的对齐**：
- 概念文档 3.1.4 时间推进系统（原"月历回合制"）——本 GDD 将其重构为"连续时间推进"，并经主理人与用户确认（AskUserQuestion 选"实时时钟+加速（推荐）"）。
- 概念文档 2.4 三支柱咬合、3.4 核心循环——本系统是三支柱共同推进的节拍器（原"每月 tick"升级为"连续时钟 + 固定步长月级结算 pass"）。
- 概念文档 R3（涌现不可控）——连续时间下涌现更不可周期预测，R13/R14 为本系统首攻的新风险。
- 概念文档 4 范围分层——MVP 单聚落连续推进 + 加速；核心层多聚落/多国家并存；延展层世纪尺度。

**设计红线（继承全局）**：玩家只调参数，绝不指挥个体/部队/指定民族或法律。连续时间不改变此原则——异步干预仍只注入间接参数（`devBias_*`、`pendingDelta`），不下达即时命令。

## 2. 机制设计（Mechanics）

### 2.1 连续时间模型（Continuous Clock）

世界时间是一个连续的"游戏时钟"，以真实墙钟时间（wall-clock）乘以速度倍率为单位推进：

| 状态 | 含义 |
|------|------|
| Pause | 时钟暂停，世界冻结（玩家可无压力地观察、布署 pending 干预、查看编年史） |
| 1× / 2× / 5× / 20× | 实时时钟 × 速度倍率推进（如 2× = 现实 1 秒 = 游戏 2 秒） |

- **无玩家回合**：时间推进不依赖玩家"结束回合"。即使玩家不操作，世界也持续演化（对齐 S2/S3 的"自治"定位）。
- **时间标度换算**（基准，待 playtest 调优）：1 游戏月 ≈ 现实 2–5 秒 @ 1×；加速倍率线性缩放。季节/年份由累计游戏月推算：
  - 每累计 3 游戏月 = 1 季（春/夏/秋/冬循环，对齐 S2 2.6 季节定义）；
  - 每累计 12 游戏月 = 1 游戏年；
  - 时代门槛由「科技层级 + 当前科技下承载力利用率 + 持续食物盈余 + 分工/治理/法制」联合判定（**禁绝对人口门闩**；见 S3 §2.0.2 v1.4.4）。

**设计意图**：连续时钟给玩家"活的世界"的体感——文明在玩家观察时也在生长、个体在衰老、灾害在酝酿；加速让玩家能快进无聊期、聚焦关键期，但快进不改变模拟粒度（仍是逐月级结算 pass）。

### 2.2 固定步长结算（Fixed Timestep / 整数序号派生边界，R-N1 修订）

表现层连续，模拟层固定步长——二者通过 **accumulator** 解耦：

```
// 连续时间驱动的双频固定步长结算（混合架构，见 §2.7）
float gameClock;            // 连续游戏时钟（游戏秒）
int   monthIndex;           // 已通过的月边界数（整数序号，月边界派生源；R-N1）
int   weekIndex;            // 已通过的周边界数（整数序号，周边界派生源；R-N1）
const float MONTH_SECONDS = 实时基准 * 速度倍率;  // 1 游戏月对应的游戏秒
const float WEEK_SECONDS  = MONTH_SECONDS / 4;    // 1 游戏周 ≈ 1/4 月
HashSet<int> activeEntities;  // 脏标记：交战军队 / 受灾聚落 / 建设中的城市
// R-N1（Gate-0 防分叉，P0）：边界由整数序号派生，禁止 float 累加器减法逼近，
// 否则长程（≥120 游戏月）1×/20× 舍入差导致边界错位、Replay 分叉。

void Update(float dtReal) {
    if (paused) return;
    float dtGame = dtReal * speedMultiplier;   // 连续推进
    // R-N1（Gate-0 防分叉）：边界由整数序号派生，比较 gameClock < nextBoundary，
    // 禁止累加器减法（monthAccumulator -= MONTH_SECONDS）逼近边界，避免长程舍入漂移。
    float target = gameClock + dtGame;
    while (true) {
        float nextMonth = (monthIndex + 1) * MONTH_SECONDS;  // 整数月序号派生，无漂移
        float nextWeek  = (weekIndex  + 1) * WEEK_SECONDS;   // 整数周序号派生，无漂移
        float next = min(nextWeek, nextMonth);
        if (next > target) break;
        gameClock = next;
        if (next == nextWeek)  { RunWeeklySubSettlement(activeEntities); weekIndex++; }  // 同刻 week 先
        if (next == nextMonth) { RunMonthlySettlementPass();           monthIndex++; } // 同刻 month 后
    }
    gameClock = target;  // 剩余不足一个边界的时间仅推进表现层（插值）
}

// 周级子结算：轻量增量刷新，仅激活实体（§2.7）
void RunWeeklySubSettlement(HashSet<int> active) {
    foreach (id in active) {
        // 资源流 / 行军进度（交战军队）
        // 灾害衰减 / 恢复（受灾聚落）
        // 建设进度（建设中的城市）
        // 不重算人口总量 / 国土 / 科技 / 国运（那是月级大账的职责）
    }
    // 解除已平息的激活标记（仗打完 / 灾害结束 / 建设完工）→ 移出 active
}

void RunMonthlySettlementPass() {
    // 驱动 S2 生态月结 + S3 文明月结（原月度 tick 流水线，见 S3 §4.3）
    // 结算 S1 干预 pending 队列（延迟到期生效）
    // 推进世代事件（个体 ageMonths 增长、死亡/继承）
    // 推进季节/年份/时代过渡计数
    // 国家层聚合（Σ 下辖聚落 → 总人口/总产出/总军力/稳定度）
    // 重新评估 activeEntities 激活标记（新增 / 解除）
}
```

**关键语义**：
- **"月"仍是模拟粒度**，但**不是玩家回合**。玩家可以随时暂停/加速；结算 pass 只在 `monthIndex` 跨过下一月边界（整数序号派生，R-N1）时静默触发，与玩家任何操作解耦。
- 固定步长保证**确定性**：相同初始种子 + 相同干预序列 → 相同演化（R13 攻关基础）。
- 加速（2×/5×/20×）只是让 `dtGame` 更大、每现实秒触发更多结算 pass，**不改变单个 pass 的内容**，因此加速下模拟仍是确定性的（R14 攻关的前提）。
- **结算分双层（v1.0.1，见 §2.7）**：月级大账遍历全量（人口/国土/科技/国运），周级子结算仅遍历激活实体（战事/灾害/建设），静默实体不重算——既保有短期细节又不失控算力。

### 2.3 干预异步（Asynchronous Intervention）

玩家干预**不即时生效**，而是进入 pending 队列，按延迟在连续时间中异步结算（与 S1 一致）：

| 属性 | 值 |
|------|-----|
| 生效时机 | 干预进入 `pendingQueue`，按声明延迟（N 游戏日 / N 游戏月）在后续某个结算 pass 中生效 |
| 延迟示例 | 气候调节渐变 1 游戏月到位；文明引导倾向持续 3–5 游戏月后衰减；资源投放落点即时生成但生态响应随 pass 渐变 |
| 紧急干预 | 保留 S1 的 24 游戏月冷却（天降甘霖/神佑护盾/生命之泉），冷却由 S4 时钟驱动递减 |
| 与回合解耦 | pending 队列由 S4 连续时钟结算，不存在"玩家回合起始"边界 |

**设计意图**：异步延迟让"干预有后果但不即时可控"（R2）在连续时间下依然成立——玩家在 t 时刻布署的干预，其末端后果在 t+Δ 的连续时间中显现，因果链可追溯（S1 因果链节点以游戏时间戳锚定）。

### 2.4 时间尺度跃迁（Scale Leaping / LOD）

同一套连续时间驱动四级尺度，LOD 决定模拟精度：

| 尺度 | 模拟精度 | LOD 策略 |
|------|---------|---------|
| 个体级（天/周） | 关键个体（统治者/匠师/学者）带精细状态机、关系、记忆 | 仅关键人物精细模拟；其余按群体/聚合统计（S3 §2.12） |
| 聚落级（月/年） | 单聚落内个体/代理微观模拟（村~市看得见人） | 聚焦聚落跑完整微观模拟；非聚焦聚落降精度 |
| 国家/文明级（月/年） | 聚合统计：总人口、总产出、总军力、稳定度 | **仅聚合统计，不逐个模拟国民**（呼应 S3 第 848 行"人口分层聚合模拟"） |
| 世代级（十年/百年） | 关键人物更替、制度惯性、文明记忆累积 | 由连续时间中的继承/更替事件驱动，跨代编年史 |

**LOD 切换**：聚焦某聚落 → 该聚落升为微观模拟；视野拉远/低焦点 → 该聚落降为聚合统计。远处/低焦点的国家层只保留聚合数值，避免"千万人口逐个 NPC"的性能灾难（T1/T4 关联）。

### 2.5 世代传承（Generational Inheritance）

个体生命周期在连续时间中推进（对齐 S3 §2.6）：

```
struct Individual {
    int id; int ageMonths;          // 月龄：在连续时间中逐 pass 增长
    ...
}
// 每个结算 pass：ageMonths += 1（月级粒度）
// 越过寿命阈值 → 触发死亡事件 → 角色/财产/知识/关系由继承人继承（D5 跨代记忆）
```

- **个体世代**：死亡触发继承，文明记忆以编年史累积（S6）。
- **文明级"世代"**：不绑定单一个体寿命，而由"关键人物更替"（如统治者继承）或"制度惯性"（如朝代/宪法周期）定义——连续时间中，当权力交接或制度范式转换发生时，标记一个新的文明世代节点。

**设计意图**：世代传承从"回合计数"变为"连续生命事件"——玩家的文明会在其观察中自然老去、易主、重生，制造"历史纵深感"而非"数据堆积感"。

### 2.6 与 S1/S2/S3 的接口

- S4 是"心跳"——`RunMonthlySettlementPass()` 依次驱动 S2 生态月结、S3 文明月结、S1 干预结算、世代事件。
- S4 向 S1 暴露时间流速参数（pause / 速度倍率），玩家经 UI 调节（可选远景层暴露更粗的时间尺度）。
- S2/S3 的"月度 tick"接口契约不变，只是调用方从"玩家结束回合"改为"S4 月边界序号跨过下一月边界（整数序号派生，R-N1）"。

### 2.7 混合结算架构（Hybrid Settlement：全局月级大账 + 事件驱动周级子结算）— v1.0.1 新增

> **来源（用户指令，2026-08-12）**：此前开放点"MVP 结算粒度维持月级是否够细"的正式结论——**不纯月级、也不全局周级，采用混合架构**：全局大账按月统一算（人口总量/国土/科技/国运），局部动态逻辑单独开周结算，且**不全局重算所有文明**。本节能把"够细的短期细节（季节、短期战事、建设）"与"可控的算力"兼得，并闭环该开放点。

**两条互不替代的结算通道**：

| 通道 | 频率 | 范围 | 算什么 | 算力占比 |
|------|------|------|--------|---------|
| **全局月级大账（Macro Pass）** | 每累计 1 游戏月 | **全部落、全文明**（遍历全世界） | 人口总量、国土、科技、国运（national fortune）的总账；驱动 S2/S3 完整月结、世代、时代、国家聚合、S1 pending 结算 | ~90% |
| **局部周级子结算（Micro/Active Pass）** | 每累计 1/4 游戏月（=1 周） | **仅 activeEntities 集合**（事件驱动的脏标记） | 轻量增量刷新：交战军队的资源流/行军进度、受灾聚落的灾害衰减/恢复、建设中的城市的建设进度；**不重算人口总量/国土/科技/国运** | ~10%（整体约纯月级 1.5–2 倍） |

**激活判定（谁进 activeEntities）**——满足任一即标记，每结算周期（月级大账时）重新评估：
- 存在**交战军队**（战争状态，`atWar == true`）；
- 存在**受灾聚落**（灾害/应力区触发，`underDisaster == true`）；
- 存在**建设中的城市/建筑**（`constructionActive == true`）；
- （可扩展）其他快速变化状态（如活跃干预落点的生态响应）经设计时追加。

**跳过规则**：和平、无建设、无灾害的文明/实体**不进入周级子结算**，仅等待月级大账——这是算力优势的来源（核心层多文明并存时，绝大多数实体处于"静默"状态）。

**与 §2.2 边界派生的关系（R-N1）**：周级边界由 `weekIndex` 序号派生（`nextWeekBoundary = (weekIndex + 1) * WEEK_SECONDS`），月级由 `monthIndex` 派生；二者在统一 `Update` 循环内按边界时间戳升序合并（§7.3）。`RunWeeklySubSettlement()` **只遍历 `activeEntities`**（脏集合），而非全世界；`RunMonthlySettlementPass()` 仍遍历全量并负责重新评估激活标记。

**确定性（R13）保持**：周级是**时间驱动**（累计满 1 周触发）而非**帧驱动**（每帧），因此与月级同属固定步长家族；加速（2×/5×/20×）只让 `dtGame` 更大、每现实秒触发更多周/月 pass，**不改变单个 pass 的内容与触发顺序**，加速下模拟仍确定可重放（R14 前提不变）。

> **实现层硬约束（v1.0.2，以 §7.3 为准）**：混合结算引入了两处确定性隐患——① 高速下一次 `Update` 跨越多个周/月边界时的**执行顺序**；② `activeEntities` 作为哈希集合的**迭代顺序不确定**。二者已在 §7.3 五条铁律中收口（按边界时间戳升序合并执行、同刻 week 先 month 后；脏集合必须按稳定 ID 排序后遍历）。**§2.2 的双频边界伪代码（R-N1 后改为整数序号派生）为简化示意，实装以 §7.3 修正版伪代码为准。**

**算力模型（用户给出并经采纳）**：整体约为纯月级的 **1.5–2 倍**，远低于"全局每局均周级结算"（那会是纯月级的 ~4–30 倍）。适配绝大多数古代王朝/文明模拟：持续实时推进不卡顿，同时保有季节、短期战事细节。

**设计意图**：这是对 §2.4 尺度跃迁（LOD）的"时间维"补充——**活跃实体获得更细的时间粒度（周级），静默实体保持粗粒度（月级）**，以最小代价换取短期动态的真实感。

## 3. 动态行为（Dynamics）

### 3.1 预期涌现行为

**D-T1 — 连续演化中的非周期涌现（Non-periodic Emergence）**
> 去除固定回合后，生态/文明的波动不再整齐地"每 N 月"重复，而是随连续干预与随机种子在真实时间轴上非周期地起伏。玩家加速 20× 快进旱季、再切回 1× 观察雨季恢复——世界不因为"被快进"而改变演化逻辑。

**GDD 对策**：固定步长保证"快进≠失真"；季节/年份由累计游戏月推算，加速只是压缩现实时间，不改变月级模拟粒度（R14 攻关基础）。

**D-T2 — 异步干预的因果漂移（Causal Drift）**
> 玩家在春天布署降雨，但干预在 1 游戏月后才渐变到位、再 2–3 个 pass 才传导到下游鱼群——当玩家加速时，这些延迟在现实中几秒就过去，但因果链仍以游戏月为单位展开，UI 以时间戳呈现"此事件源于 N 游戏月前的干预"。

**GDD 对策**：因果链节点以游戏时间戳（非回合号）锚定，连续时间下仍可精确追溯（S1 R1 agency 感延续）。

**D-T3 — 尺度跃迁的视觉/认知跳变（LOD Pop-in）**
> 玩家从单聚落的微观沙盒拉远到国家聚合视图，人口从"数百可见的 NPC"跳变为"千万级聚合数字"——若过渡不平滑，玩家会失去对规模的直觉。

**GDD 对策**：LOD 分级渐进（个体→群体统计→聚合），聚焦聚落保持微观、非聚焦降精度；国家层只呈现聚合统计，明确"这是统计值不是逐人模拟"，避免误导。

### 3.2 边界情况

| 边界情况 | 处理方式 |
|----------|---------|
| 玩家一直暂停 | 世界冻结，无结算 pass；UI 提示"世界已暂停"，玩家可无压观察/布署 |
| 20× 加速下长时间运行 | 每现实秒触发多个结算 pass，性能压力上移；靠固定步长 + 聚落/国家 LOD 控制（远处聚落降精度、国家仅聚合） |
| 存档/读档 | 序列化 `gameClock` + `monthIndex`/`weekIndex`（整数序号，取代易漂移的 float 累加器，R-N1）+ 各系统状态；固定步长保证读档后演化可重放（R13） |
| 干预延迟跨越暂停 | pending 延迟以游戏时间计，暂停不消耗延迟；恢复后继续倒计时 |
| 世代事件与结算 pass 冲突 | 死亡/继承在结算 pass 内串行处理，避免并发状态撕裂 |

| S9 相机系统 | S4 ↔ S9 | 相机焦点联动 LOD（聚焦聚落=微观，拉远=聚合）；时间尺度联动 |

### 4.3 结算 pass 驱动顺序（"心跳"时序）

```
// 月级大账（每累计 1 游戏月，遍历全量，见 §2.7 全局月级大账）
每个结算 pass（每累计 1 游戏月）：
1. 读取 S1 干预 pending 队列 → 延迟到期的干预生效（写入 devBias_*/pendingDelta）
2. 推进季节计数（每 3 游戏月切换季节）→ 更新 SeasonalProfile
3. 驱动 S2 生态月结（种群/食物链/资源/地貌/指标，原 S2 §4.3 流水线）
4. 驱动 S3 文明月结（个体→经济→聚落→科技→社会→宗教→文化→族群→法律→政治→军事→时代，原 S3 §4.3 顺序）
5. 世代事件：个体 ageMonths 增长 → 越过寿命阈值触发死亡/继承；文明级世代节点判定
6. 国家层聚合：Σ 下辖聚落统计 → nation.population / 总产出 / 总军力 / 稳定度（不逐人模拟）
7. 重新评估 activeEntities 激活标记（新增/解除交战、灾害、建设状态）
8. 输出事件 → S6（叙事）/ S8（UI）

> **周级子结算穿插其间（§2.7）**：相邻两次月级大账之间会触发约 4 次周级子结算（`RunWeeklySubSettlement`），仅刷新当前 `activeEntities` 的局部动态（战事/灾害/建设进度），**不重算全局总账**；月级大账的第 7 步负责重算激活标记，故周级只处理已活跃实体。这把"短期战事/季节细节"与"可控算力"兼得。
```

### 7.2 验证时机

- V2（R13）是连续时间模型的**前提**——若不可重放，需回退到更严格的固定步长；**V2 即 §7.3 Gate-0 的判定用例**
- V3（R14）与 V2 协同：确定性成立后才谈加速下的涌现体验

### 7.3 R13 确定性 P0 前提裁决（Gate-0）— v1.0.2 新增

> **裁决（闭环开放点）**：**是** —— R13（连续时间确定性/可重放）确认为 **P0 前提**，并升级为 **Phase 3 技术垂直切片的第一道里程碑门（Gate-0）**。理由：连续时间是本项目最底层的范式赌注，S2 生态、S3 文明、S1 因果链、存读档、混合结算全部挂在它上面。**若确定性不成立，后续系统的所有 playtest 数据都不可复现、bug 不可定位、平衡不可调**——那是返工成本最高的一类失败。因此 **Gate-0 未通过，不得进入后续系统实装**（先修确定性，再谈内容）。

**Gate-0 测试规范（Replay 一致性测试）**

| 项 | 规定 |
|----|------|
| 输入 | 同一 `worldSeed` + 同一干预序列（以**游戏时间戳**而非现实时间记录的脚本，回放时按游戏时钟注入） |
| 四路对跑 | ① 全程 1× ② 全程 20× ③ 中途变速（1×→20×→1×，含多次暂停） ④ 中途存档→退出→读档续跑 |
| 时长 | ≥ 120 游戏月（含至少 1 次时代过渡 + 1 次战事 + 1 次灾害，确保周级子结算通道被覆盖） |
| 比对方式 | 每个月级大账结束时对世界状态取**指标哈希**（人口/资源/物种量/科技/稳定度/军力/RNG 状态），逐月比对四路哈希序列 |
| 通过标准 | 四路哈希序列**逐月完全一致**（浮点量先量化到固定精度再入哈希）；任一月出现分叉即失败，并输出首个分叉月用于定位 |

**五条确定性实现铁律（Phase 3 实装必须遵守）**

1. **固定步长是唯一时间源**：所有子系统只能读 `gameClock` 与 pass 序号，**禁止**读取 `Time.deltaTime`、墙钟、系统时间或帧计数作为逻辑输入。
2. **双频 pass 按边界时间戳升序合并执行**（修正 §2.2 的"先跑完所有周 pass 再跑月 pass"写法）：在一次 `Update` 中若同时跨越多个周边界与月边界，必须把它们**按其在游戏时间轴上的实际先后**排序后依次执行；同一时刻并发时固定为 **week 先、month 后**。伪代码：

```
// 修正实现：按边界时间戳升序合并执行（20× 下跨多个边界时顺序仍确定）
// R-N1（Gate-0 防分叉，P0）：边界由整数序号派生，禁止 float 累加器减法逼近，
// 否则长程（≥120 游戏月）1×/20× 因舍入差产生边界错位、Replay 分叉。
void Update(float dtReal) {
    if (paused) return;
    float target = gameClock + dtReal * speedMultiplier;
    while (true) {
        float nextMonth = (monthIndex + 1) * MONTH_SECONDS;  // 整数月序号派生，无漂移
        float nextWeek  = (weekIndex  + 1) * WEEK_SECONDS;   // 整数周序号派生，无漂移
        float next = min(nextWeek, nextMonth);
        if (next > target) break;
        gameClock = next;
        if (next == nextWeek)  { RunWeeklySubSettlement(SortedByStableId(activeEntities)); weekIndex++; }  // 同刻 week 先
        if (next == nextMonth) { RunMonthlySettlementPass();                                 monthIndex++; } // 同刻 month 后
    }
    gameClock = target;   // 剩余不足一个边界的时间仅推进表现层
}
```

3. **遍历顺序必须稳定**：`activeEntities` 在 §2.2 声明为 `HashSet<int>`，**哈希集合的迭代顺序不是确定的**——周级子结算必须先按**稳定 ID 升序**排序再遍历（`SortedByStableId`）。同理，所有对聚落/政体/物种集合的遍历一律按稳定 ID 排序，禁止依赖字典/集合的自然顺序。
4. **RNG 按子系统分流且状态入存档**：不使用单一全局随机源。每个子系统（S2 生态 / S3 各子系统 / 灾害 / 战斗）持有由 `worldSeed` 派生的独立 RNG 流（`derive(worldSeed, systemId)`），推进只发生在结算 pass 内；**存档必须序列化每条 RNG 流的内部状态**，否则读档后分叉。
5. **禁止不确定并发与浮点漂移**：结算 pass 内若使用多线程/Job，必须保证**归约顺序固定**（先分块计算、再按固定块序合并），不得让完成顺序影响结果；跨平台浮点须统一（禁用 fast-math 类优化），必要时对关键累加量做定点化或量化写回。

**三级回退方案（Gate-0 若未通过，按序降级而非放弃连续时间）**

| 级别 | 措施 | 代价 |
|------|------|------|
| 回退 1 | 收窄速度档（去掉 20×，保留 1×/2×/5×），并把干预注入严格对齐到月边界 | 失去极速快进，体验损失小 |
| 回退 2 | 结算 pass 内全部串行化（关闭并行归约），关键浮点量定点化 | 性能下降，需靠 §2.7 混合结算与 LOD 补偿 |
| 回退 3 | 改为确定性 lockstep：表现层继续连续插值，模拟层严格离散步进且不接受任何步间输入 | 干预即时感下降（干预统一落到下一月边界生效） |

> **底线**：三级回退均**保留"连续时间"的玩家体感**（表现层始终连续插值），绝不回到月历回合制——回合制已由用户明确取消。
