WorldSim 系统索引

文档说明：本文档是 Phase 2 系统设计的入口文件，列出 WorldSim 的全部系统、依赖关系、GDD 产出优先级，并标注每个系统需要攻关的设计风险。后续逐系统 GDD 按本文档排列的顺序产出。

1. 系统总览

WorldSim 的系统分为三层：核心循环层（三支柱 + 时间）、模拟支撑层（世界生成 + 叙事 + 模块框架）、表现与交互层（UI + 相机 + 存档）。

1.1 核心循环层（Core Loop Layer）

玩家每月都会触达的系统——三支柱在此层咬合。

# 系统名 英文标识 职责一句话 P0 风险关联 GDD 优先级
S1 干预系统 InterventionSystem 玩家唯一行动接口——通过间接调节世界参数影响三支柱（干预无限次，自然后果制衡）；干预结算时机对齐 S4 连续时间（异步延迟生效，去除玩家回合边界） R1（agency 感）/ R2（干预与涌现性矛盾） ★★★ 第 1
S2 生态模拟引擎 EcologySimEngine 种群动态、食物链、资源再生、地貌演变、四季循环；时间模型对齐 S4 连续时间（固定步长月级结算） R3（涌现不可控性） ★★★ 第 2
S3 文明发展系统 CivilizationSystem 聚落成长、经济流转、科技积累、政治演变、个体生命周期、军事/战争子系统（核心层可用：多聚落模块 ON 时文明间即可开战）；含人口尺度层级（聚落分档 村/镇/市/都市圈 + 国家=多聚落聚合千万~十亿级）、族群子系统（§2.11）、跨国文化家族（§2.8）、经济/社会制度谱（§2.4.4）、法律体系家族（§2.9.1）、治理层级三轴：法理等级 × 体量规模 × 关系形态（§2.4.5 / §2.4.5.1）；时代门槛禁绝对人口门闩（§2.0.2 v1.4.4：TechTier + 盈余 + pop/CC 利用率）（核心层，默认 ON；MVP 族群折叠裁决：单一主导族群、结构保留不退化、不保留潜在分化入口） — ★★ 第 3
S4 时间推进系统 TimeProgressionSystem 连续时间推进（实时时钟+加速 1×/2×/5×/20× + 固定步长月结 + 异步干预 + 尺度跃迁 + 世代传承），替代月历回合制；v1.0.1 增混合结算架构（全局月级大账 + 事件驱动周级子结算，算力约纯月级 1.5–2×）；v1.0.2 增 §7.3「R13 确定性 P0 前提裁决（Gate-0）」（Replay 四路对跑 + 五条确定性铁律 + 三级回退） R3（涌现不可控，连续时间下更需注意）/ R13 / R14 ★★ 第 4

依赖规则： - 箭头方向 = 依赖方向（A → B 表示 A 依赖 B 的输出） - S5 是所有系统的空间基底，必须最先产出（但 GDD 可以后写，因为概念文档已定义其范围） - S1（干预系统）依赖 S2/S3/S4 的参数接口——GDD 先写 S1 定义接口契约，再由 S2/S3/S4 实现 - S6/S8 依赖所有模拟系统的状态输出——最后设计 - S7/S9/S10 是横切系统，可并行设计

3.2 P0 风险攻关映射

风险 关联系统 攻关 GDD 攻关方向
R1 间接控制 agency 感 S1 干预系统 第 1 批 即时视觉反馈（金色光环+涟漪）+ 远期后果可追踪性 + 因果链追溯 + 反噬机制——agency 感来自可见的因果影响力而非资源稀缺
R2 干预与涌现性矛盾 S1 干预系统 第 1 批 自然后果制衡（干预无限制，但过度干预触发生态反噬）+ 延迟后果 + 反噬预警；需大量 playtest 调参反噬阈值
R3 涌现不可控性与世界崩坏 S2 生态模拟引擎 第 2 批 生态稳态区间机制（正常区间自修复，过临界点才相变）+ 灾害前兆预警 + 紧急干预手段

3.3 P1 风险攻关映射

风险 关联系统 攻关 GDD 攻关方向
R4 叙事涌现可读性 S6 叙事引擎 / S8 UI 第 6/8 批 事件检测器 + 叙事呈现层——卷轴式通知 + 编年史 + 关键个体高亮
R5 认知过载风险 S8 UI/HUD 第 8 批 信息分层呈现（总览→详情→逐项）+ 智能事件筛选 + 可自定义关注焦点

R10 双模式参数化一致性 S5 地图 / S3 文明 第 5 批 锁定 IWorldGeography 单一地理查询入口，两模式仅差异在 WorldInitConfig，地理机制完全一致
R11 军事平衡 S3 军事/战争子系统 第 3 批 军费/战损/战争疲劳三重成本（经济+生态+政治）+ 战略层仅偏移权重不指挥，避免「军事主导策略」

4. GDD 文档模板

每个系统 GDD 遵循以下八节结构（短系统可合并为 4-6 节）：

---
项目名: WorldSim
文档名: [系统名] GDD（Game Design Document）
版本: v1.0.0
日期: [日期]
作者: [作者]
阶段: Phase 2 — 系统设计
输入文档: systems-index.md + game-concept.md
状态: 草稿（待评审）
---

# [系统名] GDD

## 1. 系统概述（System Overview）
- 一句话定义
- 设计目标（本系统解决什么问题）
- 与概念文档的对齐（引用 MDA/范围分层中的相关条目）

## 2. 机制设计（Mechanics）
- 核心机制列表（每个机制含：名称、描述、参数、作用域）
- 数据模型（关键数据结构、状态机、参数表）
- 算法/公式（如涉及模拟计算）

## 3. 动态行为（Dynamics）
- 涌现行为预测（机制交互产生的预期/非预期行为）
- 边界情况与极端状态

## 4. 系统交互（System Interactions）
- 与其他系统的接口（输入/输出/事件）
- 依赖关系图（本系统在依赖链中的位置）

## 5. 范围分层（Scope Layering）
- MVP 范围（最小实现）
- 核心层范围（完整实现）
- 延展层范围（扩展方向）

## 6. 风险与未决问题
- 本系统特有的设计风险
- 需 playtest 验证的假设
- 与 P0/P1 风险的关联

## 7. 验证标准（Validation Criteria）
- MVP 验证假设列表
- 通过/不通过的判定标准
- 验证方法（原型/playtest/数据观察）

## 8. 评审检查清单
- 逐条检查项 + 通过标准 + 状态
