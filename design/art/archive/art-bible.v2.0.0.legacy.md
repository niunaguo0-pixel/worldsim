# WorldSim 美术圣经

> **文档说明**：本文档基于概念文档第 5 章"视觉锚点"产出，作为后续所有美术资源的基准规范。核心理念是"微缩沙盘手绘风格"——全时代一套美术风格，文明演进通过建筑形态、技术产物的内容变化传达，而非画面风格突变。所有美术人员（原画、3D、TA、UI、特效）须以本文档为唯一风格参照。

---

## 1. 视觉身份概述（Visual Identity Overview）

**一句话定义**：WorldSim 的视觉身份是"桌面上的活微缩世界"——玩家俯瞰一座手绘质感的微缩沙盘，世界中的万物以低多边形 + 手绘纹理呈现，始终维持统一的温润质感与尺度感。

**核心视觉理念：全时代统一微缩沙盘风格（Unified Diorama Style）**

本作最重要的视觉决策：美术风格全时代统一。无论文明处于远古洪荒还是现代都市，画面始终保持一致的微缩沙盘视觉语言。文明从茅棚到城邦到都市的演进，通过建筑形态、聚落规模、技术产物的变化来传达，画面风格本身始终如一。

| 原则 | 说明 |
|------|------|
| 风格统一 | 全时代一套美术风格，不因文明阶段切换画面画风——时代感来自内容（建筑/技术/社会形态），不来自画风突变 |
| 微缩尺度 | 世界像一座可俯瞰的掌中微缩模型，有"桌面上的一盘小世界"的亲昵感与尺度感 |
| 手绘温度 | 低多边形 3D + 手绘纹理（Hand-Painted Texture），NPR 非写实渲染，画面有"人手做出来"的温度感 |
| 俯视可读 | 所有美术资源服务于俯瞰视角下的信息可读性——玩家一眼读懂地形、聚落、状态 |

**视觉目标**：玩家从开局到终局看到的是同一个世界的同一种画风——微缩沙盘上手绘质感的小世界。文明演进通过内容变化（建筑形态、聚落密度、技术产物）传达，画面风格本身始终如一。

**六大风格关键词**（详见概念文档 5.1）：

1. **微缩沙盘（Diorama）** — 可俯瞰的掌中世界尺度感
2. **手绘温度（Hand-Painted Warmth）** — 手绘纹理赋予画面温度感与匠人气质
3. **层次分明（Layered Depth）** — 地形高低、植被疏密、聚落分布形成纵深
4. **生机盎然（Lived-in Vitality）** — 炊烟、田垄、兽迹、水纹都在动
5. **史诗质感（Epic Texture）** — 微缩尺度中蕴含宏大气象
6. **俯视可读（Top-Down Readability）** — 俯瞰视角下一切信息一目了然

**与 v1.0.0 的核心差异**：

| 维度 | v1.0.0（已废弃） | v2.0.0（当前） |
|------|-----------------|---------------|
| 风格理念 | 风格随时代演进（Style Evolution） | 全时代统一微缩沙盘风格 |
| 时代表达 | 画面风格变化传达时代感 | 建筑形态/技术产物变化传达时代感 |
| Shader 系统 | Universal Era Shader + _EraProgress 参数 | 统一手绘风格 Shader，无需时代过渡 |
| 色彩系统 | 四时代各自色板 + 过渡插值 | 单一色板 + 季节/灾害动态调色 |
| UI 系统 | 古代卷轴 UI ↔ 现代数据面板 UI 过渡 | 统一半透明手绘风 UI |
| 技术复杂度 | 高（需实现风格平滑过渡） | 中（无需过渡机制，专注统一风格品质） |

## 2. 风格指南（Style Guide）

### 2.1 渲染特征

**整体渲染定位**：NPR（Non-Photorealistic Rendering）手绘卡通风风格，低多边形建模 + 手绘纹理贴图。画面追求"桌面微缩模型"的质感——不是写实，不是像素，不是水墨，而是有手作温度的 3D 微缩世界。

**渲染技术要点**：
- 低多边形建模（Low-Poly），面数克制，轮廓清晰
- 手绘纹理（Hand-Painted Texture），笔触可见，有"画上去"的质感
- 柔和方向光 + 环境光，阴影柔和不锐利
- 微缩尺度阴影——阴影距离短、偏移小，营造"小世界"感
- 无 PBR 写实材质——所有材质走手绘风，不依赖物理光照计算
- 边缘描边（Outline）可选——建筑/角色可加细描边增强可读性

**统一色板**（全时代通用）：

### 2.3 线条与笔触规范

- 地形轮廓：自然曲线，手绘质感的高度图 mesh
- 水面：规整波纹纹理，有方向性，半透明
- 植被：低多边形树冠/草丛 + 手绘纹理，叶形可辨但不写实
- 建筑：低多边形 + 手绘木纹/瓦片纹理，直线为主但有手绘温度
- NPC：简化人形轮廓（俯视下约 3-5mm 等效），可辨姿态与职业

### 2.4 材质方向

| 材质类型 | 实现方式 | 说明 |
|----------|---------|------|
| 地形 | 高度图驱动 mesh + 手绘纹理 | 程序化生成高度图，手绘纹理按高度/坡度分配 |
| 水面 | 半透明 + 波纹法线 + 简单反射 | 不追求写实水面，保持手绘质感 |
| 植被 | 低多边形 + 手绘纹理 | 树冠/草丛用低模 + 手绘叶纹纹理 |
| 建筑 | 低多边形 + 手绘纹理 | 木纹、瓦片、砖石纹理均为手绘风格 |
| NPC | 低多边形 + 纯色 + 简单纹理 | 俯视下极小，以颜色和轮廓区分职业 |

### 2.5 光影方向

| 光照项 | 设定 | 理由 |
|--------|------|------|
| 主光源 | 柔和方向光（45°-60° 倾斜） | 模拟自然日光，与俯视相机角度配合 |
| 环境光 | 全局环境光（天空色驱动） | 保证阴影面不过暗，维持手绘质感 |
| 阴影 | Soft Shadows，Shadow Distance ≤ 50m | 微缩尺度下阴影距离短，保证性能 |
| 阴影偏移 | 小偏移，短投影 | 营造"小世界"尺度感 |
| 四季色温 | 全局光照色温随季节变化 | 春暖偏黄 / 秋冷偏橙 / 冬冷偏蓝 |
| 灾害光照 | 灾害时全局压暗 + 偏色 | 见第 3 章灾害调色 |
| 暖色点缀 | 聚落炊烟区域微弱暖色点光 | 营造"有人住"的生机感 |

## 4. 地形与环境美术（Terrain & Environment Art）

### 4.1 类现实世界地图的视觉呈现方向

世界地图为程序化生成的大陆级地图，俯视呈现。视觉上需传达"微缩沙盘"的尺度感——不是卫星照片的真实感，而是"桌面上的一盘微缩世界"。

**地图视觉层级**（从底到顶）：

| 层级 | 内容 | 渲染方式 |
|------|------|---------|
| L0 底层 | 海洋/大水体 | 半透明水面 + 深浅渐变 |
| L1 地形层 | 山脉/平原/森林/荒漠 | 高度图驱动 mesh + 手绘纹理 |
| L2 植被层 | 草地/树木/灌木 | 低模 + 手绘纹理 |
| L3 建筑层 | 聚落/城市/基础设施 | 低模 + 手绘纹理 |
| L4 动态层 | NPC/动物/天气粒子 | 粒子/点状 sprite |
| L5 特效层 | 干预光效/灾害特效 | 粒子 + shader |
| L6 UI 叠加层 | 标记/面板/光标 | uGUI Canvas |

### 4.2 各生物群系美术特征

> 全时代统一——同一生物群系始终使用相同的美术表现，不因文明阶段而变化。

| 天气类型 | 视觉效果 | 说明 |
|----------|---------|------|
| 晴天 | 清晰可见，柔和日光 | 暖光柔角，阴影短 |
| 多云 | 半透明云阴影在地表移动 | 云阴影柔和 |

## 5. 建筑与聚落美术（Architecture & Settlement Art）

### 5.1 建筑风格方向

> 全时代统一的渲染风格——所有建筑都是低多边形 + 手绘纹理。建筑的变化是形态与内容层面的（茅棚 → 木构 → 砖石 → … → 现代高楼），而非画风层面的。

建筑演进路径（按文明技术等级，非美术风格切换）：

| 技术等级 | 建筑类型 | 美术特征 | 色彩 | 模型面数 |
|----------|---------|---------|------|---------|
| T0 原始 | 茅棚/窝棚 | 极简三角形态，茅草顶 | 土黄 `#C4A35A` + 赭石 `#8B5E3C` | ≤50 面 |
| T1 古代早期 | 木构建筑 | 榫卯结构感，木墙瓦顶 | 赭石 `#8B5E3C` + 石青 `#3A6B8C`（屋顶） | 100-200 面 |
| T2 古代鼎盛 | 石木混合 | 石基木墙，有围墙院落 | 岩石灰 `#6B6B6B` + 赭石 `#8B5E3C` | 200-400 面 |
| T3 城邦 | 多层建筑 | 有城防工事，路网 | 岩石灰 `#6B6B6B` + 土黄 `#C4A35A` | 300-600 面 |
| T4 中古 | 砖石城堡 | 砖墙、城墙、塔楼 | 砖红 `#9C5B4A` + 岩石灰 `#6B6B6B` | 400-800 面 |
| T5 近代 | 工业建筑 | 工厂、烟囱、砖石+铁构件 | 工业暖灰 `#9A9088` + 砖红 `#9C5B4A` | 400-800 面 |
| T6 现代 | 现代建筑 | 高楼、玻璃幕墙、道路网 | 岩石灰 `#6B6B6B` + 水面灰蓝 `#5E7A8C`（玻璃） | 300-600 面 |

**关键说明**：所有技术等级的建筑使用相同的手绘纹理风格和渲染管线——T6 现代高楼与 T0 茅棚在画风上完全一致（低多边形 + 手绘纹理），只是形态和材质纹理不同（玻璃 vs 茅草）。这是"全时代统一风格"的核心体现。

建筑模型规范：
- 每个技术等级 3-5 种变体（民居/仓储/生产/防御/特殊）
- 模块化组件：屋顶/墙体/地基可自由组合
- 俯视可读性：屋顶是俯视下最主要的识别面——通过屋顶形状/颜色区分功能

### 5.2 聚落成长可视化

聚落成长分为 5 个视觉阶段，玩家通过画面直接读出聚落规模：

| 阶段 | 名称 | 人口 | 视觉标志 | 画面占地面 |
|------|------|------|---------|-----------|
| S0 | 露营点 | 1-5 | 1-2 个茅棚，无固定设施 | 极小（点状） |
| S1 | 村落 | 5-20 | 5-8 个建筑，有简单田垄 | 小 |
| S2 | 聚落 | 20-50 | 10-15 个建筑，有仓储/生产区 | 中 |
| S3 | 城镇 | 50-200 | 建筑密集，有围墙/集市 | 大 |
| S4 | 城邦 | 200+ | 多层建筑，城防工事，路网 | 很大 |

聚落成长动画：新建筑以"从地面生长"的方式出现，持续约 2 秒——地基先出现，然后墙体升起，最后屋顶落定。全时代统一动画风格。

**整体风格**：半透明手绘风面板、简洁图标、可读性优先。全时代统一——不因文明阶段切换 UI 风格。

### 7.2 关键 UI 元素设计方向

#### 信息面板

可折叠侧边面板，默认收起，hover 展开。分三层级：总览（聚落状态概览）→ 详情（人口/粮储/经济/科技）→ 逐项（可点击查看单条数据）。半透明底色不遮挡世界画面。数据以清晰数值/进度条呈现，关键数值用暖金标注。

#### 地图标记

| 标记类型 | 形态 | 色彩 |
|----------|------|------|
| 聚落 | "屋"形手绘图标 + 人口数值 | 深褐 `#3A2A1A` |
| 物种 | "足印"手绘图标 | 深褐 `#3A2A1A` |
| 资源 | "圆点"手绘图标 + 数值 | 深褐 `#3A2A1A` |
| 灾害 | 朱砂惊叹符 | 朱砂红 `#C0392B` |
| 干预落点 | 金色光环 + 涟漪 | 暖金 `#D4A84B` |

#### 干预光标

金色光环（内圈实心 + 外圈渐隐），释放时涟漪从落点向外扩散 2-3 圈，渐隐。色彩：暖金 `#D4A84B` + 朱砂 `#C0392B`。全时代统一。

#### 时间轴

底部细条形态。轴体为半透明条状，季节/年份以无衬线体小字标注。可拖拽加速/暂停；不同时间尺度下刻度自动切换。

#### 事件提示

右侧浮现的通知卡片，滑入动画（从右滑入，约 0.3s）。简洁卡片式，半透明底色。

事件分级配色：

| 级别 | 色彩 | 说明 |
|------|------|------|
| 正面 | 暖金 `#D4A84B` | 丰收、发现、灵感 |
| 中性 | 深褐 `#3A2A1A` | 常规信息 |
| 警告 | 朱砂红 `#C0392B` | 灾害前兆、资源告急 |
| 紧急 | 朱砂红 `#C0392B` 闪烁 | 文明存亡危机 |

#### 编年史

全屏阅览视图，打开时画面淡出为暗色铺底。文字以编年体格式排列，可上下滚动翻阅、搜索/筛选/缩放。

## 9. 技术美术方向（Technical Art Direction）

### 9.1 URP 渲染管线配置方向

| 配置项 | 设定 | 理由 |
|--------|------|------|
| 渲染管线 | URP 17.0.4 | 概念文档已确认 |
| 相机 | 正交相机（Orthographic）+ 可选透视微调 | 俯视沙盘视角，正交保证一致性 |
| 相机角度 | 45°-60° 倾斜俯视 | 既能看到地面布局，又有微缩纵深感 |
| 阴影 | Soft Shadows，Shadow Distance ≤ 50m | 微缩尺度下阴影距离短，保证性能 |
| 抗锯齿 | FXAA 或 SMAA | 性能优先，微缩尺度下 TAA 可能导致抖动 |
| 色彩空间 | Linear | 保证 shader 和后处理的色彩准确性 |
| HDR | 开启 | 后处理 Bloom（干预光效）需要 HDR |
| MSAA | 关闭（用 FXAA 替代） | URP 下 MSAA 与某些 shader feature 不兼容 |

### 9.2 统一 Shader 方案

> v2.0.0 不再需要 Universal Era Shader 和 `_EraProgress` 参数。全时代使用同一套 Shader，无需风格过渡。

**核心 Shader**：WorldSim Hand-Painted Shader

基于 URP Shader Graph 构建，支持手绘纹理风格的 NPR 渲染：

```
[WorldSim Hand-Painted Shader Graph]

输入：
  - Base Color（手绘基础色纹理）
  - Normal（手绘法线贴图，可选）
  - Occlusion（手绘 AO 贴图，可选）
  - Rim Light Color（边缘光颜色，用于增强可读性）

逻辑：
  1. 基础色：采样手绘纹理
  2. 光照：柔和方向光 + 环境光（URP Lit 基础上降低 PBR 权重）
  3. 边缘光：Fresnel 边缘光，增强物体轮廓可读性
  4. 饱和度：全局后处理控制（见 9.4）

输出：
  - Albedo（手绘基础色）
  - Normal（手绘法线）
  - Emission（干预光效/灾害偏色）
```

**Shader 变体控制**：

| Shader | 用途 | 变体数 |
|--------|------|--------|
| WorldSim Hand-Painted | 建筑/地形/植被通用 | ≤ 5 |
| WorldSim Water | 水面 | ≤ 3 |
| WorldSim NPC | NPC/生物（简化版，Instancing 优化） | ≤ 3 |
| WorldSim VFX | 粒子特效 | ≤ 5 |
| UI Default | uGUI 元素 | URP 内置 |

全场景核心 Shader ≤ 5 个，变体总数 ≤ 20。

### 9.3 性能预算方向

大量实体渲染的性能策略：

| 策略 | 说明 | 适用范围 |
|------|------|---------|
| GPU Instancing | 同类建筑/植被/NPC 使用相同 mesh + material，开启 GPU Instancing | 建筑、植被、NPC |
| DOTS/ECS | NPC 与生态模拟使用 DOTS 架构，数据驱动，批量处理 | NPC（数百-数千） |
| LOD Group | 每个建筑/植被设 3 级 LOD：近（全细节）/ 中（简化）/ 远（Billboard/点） | 建筑、植被 |
| Tick-based 模拟 | 生态/经济计算按 Turn 结算（非每帧），仅渲染层每帧更新 | 生态、经济系统 |
| 视锥剔除 | URP 内置视锥剔除 + 遮挡剔除 | 全场景 |
| HLOD（层级 LOD） | 远视角下聚落合并为单一 HLOD mesh | 聚落、城市 |
| 粒子池化 | 干预特效/天气粒子使用对象池，避免运行时实例化 | 粒子特效 |

性能预算（目标 60 FPS @ 1080p，桌面 PC）：

| 项目 | 预算 |
|------|------|
| 渲染帧时间 | ≤ 12ms（剩余给模拟逻辑） |
| Draw Call | ≤ 2000（Instancing 后） |
| 三角面数 | ≤ 2M（近景全细节 + 远景 LOD） |
| 粒子数 | ≤ 5000 同屏 |
| 纹理内存 | ≤ 2GB（使用 Texture Atlas + 纹理压缩） |
| Shader 变体数 | ≤ 20 |

### 9.4 后处理方向

使用 URP Volume + Volume Override 实现：

| 后处理项 | 设定 | 理由 |
|----------|------|------|
| Color Adjustments — Saturation | -20% | 压低饱和度，维持手绘温润质感 |
| Color Adjustments — Contrast | +0% | 自然对比度 |
| Color Adjustments — Color Filter | 无（季节/灾害通过 White Balance + Filter 动态控制） | — |
| White Balance — Temperature | 随季节动态变化（+300K 春 ~ -400K 冬） | 季节色温轮转 |
| Bloom | 弱（干预光效 + 炊烟暖光） | HDR 支持下的柔和光晕 |
| Vignette | 弱 | 微缩沙盘的聚焦感 |
| Tonemapping | Neutral | 中性色调映射 |
| Color Grading LUT | 四季 LUT（×4）| 季节调色 |
| Sharpen | 无 | — |

后处理 Volume 使用 URP 的 Local Volume + Global Volume 组合：
- Global Volume：基础后处理（色温/对比度/饱和度）
- Local Volume：灾害调色 Volume，在灾害区域触发，覆盖 Global Volume
- 季节 LUT 通过 Runtime 切换 LUT Texture 实现

### 10.2 模块化与复用策略

| 策略 | 说明 | 示例 |
|------|------|------|
| 建筑模块化 | 屋顶/墙体/地基/装饰件独立制作，运行时组合 | 屋顶 5 种 × 墙体 4 种 × 地基 2 种 = 40 种组合 |
| 植被共享 mesh | 同类植物共享基础 mesh，通过缩放/旋转/纹理变化产生差异 | 松树 mesh × 3 种缩放 × 4 季纹理 = 12 种变体 |
| NPC 模板化 | 基础人形 mesh + 服饰/工具附件，按职业组合 | 基础 mesh + 3 种服饰 + 3 种工具 = 9 种组合 |
| 纹理图集 | 同类资源合并到 Atlas，减少 Draw Call | 建筑纹理 Atlas（2048×2048，含 16 个建筑纹理） |
| Shader 统一 | 尽可能使用 WorldSim Hand-Painted Shader，减少 Shader 变体数 | 全场景 ≤ 5 个核心 Shader |

### 10.3 LOD 策略

| LOD 级别 | 距离（正交相机 Size 倍数） | 面数 | 表现 |
|----------|--------------------------|------|------|
| LOD0 | 0 - 0.5× | 100% | 全细节模型 + 完整纹理 |
| LOD1 | 0.5× - 1.5× | 50% | 简化模型 + 共享纹理 |
| LOD2 | 1.5× - 3× | 20% | 极简模型 + Atlas 纹理 |
| LOD3（Billboard/点） | 3×+ | ≤10 面 | Billboard 面片 / 点 |

LOD 切换距离基于正交相机的 Size（Orthographic Size）动态计算，而非绝对距离——保证缩放视角时 LOD 正确响应。

HLOD 策略：当视角缩远到整个聚落/城市在屏幕中占面 < 10% 时，聚落内所有建筑合并为单一 HLOD mesh，面数 ≤ 500，以色块表示聚落轮廓。

## 11. 美术风险与未决问题

| # | 风险 | 优先级 | 说明 | 缓解方向 |
|---|------|--------|------|---------|
| A1 | 俯视可读性与手绘风格之间的矛盾 | P0 | 手绘纹理在俯视小尺度下可能细节过多导致辨识困难——纹理追求美感，但玩法要求信息可读。 | 1) NPC 始终保持最小可视尺寸（≥ 3mm 屏幕等效），即使远处也用点状 sprite 保底；2) 关键信息（聚落状态/灾害/资源）通过 UI 叠加层补充可读性，不完全依赖画面；3) 地形与 NPC 之间始终保持明度差 ≥ 30%；4) 手绘纹理的笔触尺度需与俯视距离匹配——远处看是色块，近处看是笔触。 |
| A2 | 建筑跨技术等级的形态差异在统一风格下的辨识度 | P1 | T0 茅棚与 T6 现代高楼在画风上完全一致（低多边形 + 手绘纹理），需要确保玩家能通过形态差异辨识技术等级，而非依赖画风变化。 | 1) 每个技术等级的建筑轮廓/剪影需有明确差异（茅棚三角 → 木构人字顶 → 砖石方盒 → 高楼矩形）；2) 屋顶颜色按技术等级渐变（茅草土黄 → 瓦顶石青 → 砖红 → 混凝土灰）；3) 聚落密度和高度随技术等级递增，从画面密度即可感知文明阶段。 |
| A3 | 四季×灾害的调色组合 | P1 | 4 个季节 × 5 种灾害 = 20 种调色组合，如果每种都用独立 LUT，资源量与维护成本较高。 | 使用参数化后处理而非独立 LUT：季节调色通过 White Balance + Color Adjustments 参数组合实现（4 组参数），灾害调色通过 Color Filter 叠加实现（5 组参数）。组合在运行时动态计算，不需要预制所有 LUT。 |
| A4 | 大量 NPC 在手绘 shader 下的渲染性能 | P1 | 数百-数千 NPC 在手绘 shader 下渲染，每个 NPC 如果独立 Draw Call 会瞬间爆。 | 1) DOTS/ECS + GPU Instancing 批量渲染；2) NPC 使用相同 material + Instanced 属性传递颜色差异；3) 远处 NPC 降级为点状 sprite（Billboard）；4) 帧率优先于个体精度——NPC 在俯视下本就是点状。 |
| A5 | 建筑模型跨技术等级替换的视觉跳变 | P2 | 建筑从木构替换为砖石再替换为混凝土，如果直接切换 mesh 会有视觉跳变。 | 1) 建筑替换分批进行（按聚落逐栋替换，非全局切换）；2) 替换时播放"生长/建造"动画（旧建筑淡出 + 新建筑从地面生长）；3) 同一建筑位的多技术等级版本共用相同地基 footprint，确保替换时位置对齐。 |
| A6 | 统一风格下远期内容（现代都市）与早期内容（远古聚落）的画面密度差异 | P2 | 虽然画风统一，但现代都市（高楼密布、道路网格）与远古聚落（几间茅棚、大片空地）的画面信息密度差异巨大，可能导致"换了个游戏"的感觉。 | 1) 这是内容层面的差异而非画风层面——通过聚落成长系统自然过渡（S0→S4 的渐进）；2) 早期阶段的空旷感是设计意图（"天地初开"），后期阶段的密集感也是设计意图（"文明拥挤"），两者都是正确的体验；3) 统一画风确保即使是现代都市，也仍然是"手绘微缩沙盘"而非"写实城市模拟"。 |

> **林绘澄注**：v2.0.0 美术圣经的核心变化是取消"风格随时代演进"，改为全时代统一的微缩沙盘手绘风格。这大幅简化了技术管线——不再需要 Universal Era Shader、_EraProgress 参数、风格过渡机制、分时代色板/UI/VFX。核心赌注从"能否实现风格平滑过渡"变为"能否在统一风格下通过建筑形态与内容变化传达足够的时代感"（A2/A6）。建议 MVP 阶段先做两件事验证：(1) 实现 WorldSim Hand-Painted Shader 原型，验证手绘纹理在俯视下的可读性与美感；(2) 制作一个包含 3 种生物群系 + 1 个聚落（T0-T2 建筑等级）的微型场景，验证统一风格下的俯视可读性（A1）与建筑技术等级辨识度（A2）。

> **与概念文档的对齐说明**：本文档所有视觉方向均基于概念文档 v1.1.0 第 5 章"视觉锚点"产出。全时代统一微缩沙盘手绘风格，与概念文档 v1.1.0 的视觉方向完全对齐。技术风险 A1 对应概念文档 T1/T4（性能与模拟计算），A4 对应 T1（大量实体渲染）。v1.0.0 中的 T7（视觉风格平滑过渡）已随概念文档 v1.1.0 取消。
